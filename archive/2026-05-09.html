Printing Press Just 10x'd Everyone's Claude Code

21.7K

Turn any tool into a token-efficient CLI for Claude Code.

Nate walks through Printing Press, a CLI factory that lets you build agent-native tools in ~10 minutes without polluting your context window — exactly the kind of practical Claude Code workflow you can copy.

details

What it is: Printing Press — a CLI factory + library of ~50 pre-built CLIs that wrap APIs, MCPs, and tools so agents like Claude Code can call them efficiently without bloating context.

The core argument (CLI > MCP > API for agents):

  • APIs: Built for code, not agents. Return massive JSON blobs, pagination/auth headaches, every token hits your context.
  • MCPs: Flexible but bloated — every MCP server loads tool definitions and descriptions into context on session start. Run `/context` in Claude Code with MCPs loaded and watch the token count balloon even when you never invoke them.
  • CLIs: Local, fast, composable, SQLite-backed, agent-native. Routing happens outside the context window — only a short summary comes back.

The killer demo:

  • Nate built a Skool CLI in ~10 minutes (Skool has no API — the CLI drives the web interface).
  • Asked Claude Code: "go to my Skool community and grab me some posts."
  • Agent used the `skool-pp` CLI, found 9 wins, filtered to the 3 strongest, returned working links.
  • Token accounting: ~260 tokens sent to Skool, ~132,000 tokens returned from Skool, but only ~2,000 tokens of summary hit Claude's context. The other 130k stayed outside the session.

How it works:

  • Printing Press ships a library of pre-built CLIs you install and immediately use.
  • Plus a factory: point it at any tool/site/API and it generates a CLI wrapper that's optimized for agent use (short outputs, clean structure, SQLite cache).
  • You can chain CLIs into skills the same way you'd compose APIs or MCPs — but without the per-call context tax.

Reference points Nate name-drops (all have official CLIs worth knowing):

  • Gemini CLI, Claude CLI, Codex CLI
  • Google Workspace CLI (`gws`) — Nate says it's his most-used tool inside Claude Code
  • GitHub CLI (`gh`), Playwright CLI
  • Higgsfield CLI, Hey CLI (recent drops)

Tools & links:

  • Printing Press (via AI Automation Society Plus) — paid community where Nate distributes the tool + courses
  • Free AI Automation Society — free resources
  • Nate's YT podcast application
  • Uppit AI (work with Nate)

Why it matters for you: If you live in Claude Code, this is the cleanest mental model yet for *why* MCPs feel heavy — and a concrete pattern (build a CLI wrapper, keep payloads outside context) you can apply to any internal tool you want an agent to drive.

The Simplest Business in a Box Anyone Can Start

2.6K

Mobile coffee cart side hustle at events.

Low-risk, low-capital side hustle: a coffee cart you can roll into events for $100–$400/hour profit with ~$1K startup vs. competitors spending $150K.

details

What it is: A turnkey mobile coffee cart business you can run at small events (festivals, markets, fairs) — pitched as a true "business in a box" anyone can start with minimal capital.

How it works:

  • Build/buy a single coffee cart for roughly $1,000 in startup costs (vs. competitors who reportedly spent $150,000 on the same setup)
  • Book two-day events — one example netted $8,000 profit in a single weekend
  • Smaller events (~80 people) clear about $400 net per day
  • Working 4–8 hours/day, that's $100–$400/hour in profit
  • Cost of failure is tiny: gas money + ~$150 for the booth/location fee if the event flops
  • Inventory doesn't spoil — coffee, cups, and ice gear (freezer) all store between events, so a bad day doesn't burn product

Why the unit economics work:

  • Coffee has fat margins and zero spoilage risk
  • Events bring captive, pre-qualified foot traffic — no marketing spend
  • One cart, one operator, no storefront, no lease
  • The original builder explicitly designed it to be operable by an "at-risk population" — divorced moms, disabled veterans — meaning the workflow is simple enough to hand off or franchise

Tools & links:

Why it matters for you: This is exactly the shiny-object side hustle profile you're hunting — sub-$1K to test, weekend-only execution, asymmetric upside ($8K weekends), and a cost-of-being-wrong measured in tanks of gas. Build one cart, work three local events, and you'll know in a month whether to scale or shelve it.

How to tell if your business will work in 59 seconds

21.5K

MOAT scoring framework to grade any business idea.

A 4-factor cheat sheet to pre-judge whether your side hustle is worth funding, fixing, or fleeing before you waste a weekend.

details

What it is: The MOAT model — a 4-pillar, 40-point ranking system to score whether a business is worth pursuing.

How it works:

  • M — Margins: Aim for 50% gross margin and 15% net margin. Below that, the math doesn't math.
  • O — Operations: Low capex wins. Can you productize services so you're not trading hours for dollars?
  • A — Advantage: Your edge — IP, network effects, headcount leverage, or ecosystem lock-in (Apple-style).
  • T — TAM: Total addressable market. Big pond or puddle?
  • Scoring: Each pillar gets 0–10. Total out of 40.
  • 0–10: Flee it. Bad model, bad business.
  • 10–20: Fix it. Salvageable but broken.
  • 30+: Fund it. Green light.

Tools & links:

  • None mentioned — framework is the tool. Codie offers to rank viewer businesses in the comments.

Why it matters for you: Before you sink nights and weekends into a side hustle, run it through MOAT — if it scores under 20, you're building a job, not a business.

Jeff Bezos's "Strong Opinions, Weakly Held" Framework

4.2K

Form sharp opinions fast, then update them on evidence.

It's the decision-making posture that separates senior engineers from fence-sitters — and it's exactly what interviewers probe for.

details

What it is: Jeff Bezos's mental model for decision-making: hold strong, well-reasoned opinions, but drop them the moment new evidence contradicts them.

How it works:

  • Strong opinions: Don't hedge. Pick a position on how things should be done and defend it with reasoning.
  • Weakly held: When new information surfaces or your understanding evolves, have the courage to flip — no ego, no sunk-cost thinking.
  • Speed matters: Get opinionated as fast as possible on a subject rather than staying neutral while you "gather more data."
  • Interview application: When prepping stories for interviews, force yourself to take a stance early — it's how you build a narrative worth telling.

How to apply it as an engineer:

  • In design reviews: come in with a recommended approach, not a list of options.
  • In code reviews: state your position clearly ("this should be X because Y") instead of vague "have you considered…"
  • In interviews: when asked "how would you build this?", commit to an architecture in the first 60 seconds, then refine as the interviewer pushes back.
  • Track when you change your mind — that's the signal you're doing it right, not a sign of weakness.

Failure modes to avoid:

  • Strong opinions, *strongly* held → dogmatic, unpromotable.
  • Weak opinions, weakly held → no signal, forgettable.
  • Strong opinions, never updated → the "that guy" on every team.

Why it matters for you: This is the posture senior engineers and staff+ candidates demonstrate by default — adopting it deliberately is one of the highest-leverage career moves you can make.
