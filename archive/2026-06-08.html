I Coached a Front-End Engineer to Sound Senior (Live)

47

Live coaching to make behavioral stories sound senior.

If you're prepping for a senior interview, this is a Bar Raiser showing exactly how to reframe your real work so it reads as senior, not mid-level.

details

What it is: A live behavioral-interview coaching session where ex-Amazon principal/Bar Raiser Steve Huyhn rewrites a real engineer's STAR story in real time.

The setup:

  • Kenan — senior front-end engineer, 6 years experience, hunting his next senior role
  • His material is solid (re-architected a costly questionnaire, hunted a nasty prod bug, drove e2e testing past team resistance) — but he tells it like a mid-level engineer
  • Steve = nearly 1,000 interviews conducted as an Amazon Bar Raiser

The three fixes Steve coaches (this is the instructional core):

  • Frontload your actions — lead with what *you* did so your impact lands in the first 30 seconds; give only enough context to make the action make sense. Don't open with a paragraph of business background.
  • Cut the 'we' / strip filler keywords — make your own contribution unmistakable. Interviewers can't credit you for what 'the team' did.
  • Tie every story to business impact — without the dollars/outcome, a good story gets misread as mid-level.

What 'too much context' looks like (Kenan's mistake):

  • He opened with white-labeling strategy, tenant customization, and the 17-question form length
  • Steve's rewrite: 'I re-architected an onboarding questionnaire that was pretty broken...' — skip the company strategy, the interviewer isn't going to work on it
  • Context isn't wrong — it's just dripped in *where each detail is needed*, not dumped up front

Senior-signal techniques in the story itself:

  • Started with a sequence diagram of the current front-end ↔ back-end flow before proposing changes
  • Made a deliberate trade-off: pushed logic to the backend (less front-end control, slightly slower API) to gain cleaner error handling
  • Broke a single-URL 17-page form into discrete paths, each with its own state context → easier to reproduce bugs, test, and reason about
  • Framed it as extensible for future SaaS-partner configuration — showing forward-looking thinking, not just a fix

Tools & links:

  • Behavioral Interview book — Steve's playbook from ~1,000 Bar Raiser interviews
  • Linear (6 months free, Business, 3 seats) — sponsor offer
  • Seattle-area + interviewing? Apply (link in video description) to be coached live on the show

Why it matters for you: This is the exact diagnosis you can't run on yourself — your stories feel senior in your head but land mid-level out loud; watch the rewrite and apply the frontload → de-'we' → business-impact pass to your own STAR answers before your next loop.

Claude Code

Claude Code on the web (research preview)

Run Claude Code in the cloud from browser or phone.

You can fire off parallel coding tasks on your static-site + Supabase repos from any browser—no local checkout—and pull them into your terminal when you want to take over.

details

What changed:

  • New surface: Claude Code on the web at claude.ai/code runs tasks on Anthropic-managed cloud VMs (also works in the Claude iOS/Android app). Research preview for Pro, Max, Team, and eligible Enterprise seats.
  • Persistent sessions — close the tab/browser and the task keeps running; monitor and review from your phone.
  • Parallel tasks — each task gets its own session and its own git branch, so you can run several at once without juggling worktrees.
  • Works on repos you don't have locally — Claude clones fresh into an isolated VM each session, makes changes, and pushes a branch for review.
  • Move work between surfaces — `claude --remote` starts a cloud session from your terminal (and can bundle a local repo without GitHub); `claude --teleport` pulls a web session back into your terminal.
  • Auto-fix pull requests — opt in to have Claude respond automatically to CI failures and reviewer comments on the PR.
  • Configurable cloud environment — network access levels (default `Trusted` allows npm/PyPI/RubyGems, blocks general internet), env vars (`.env` format), and a cached Bash setup script (e.g. `apt install -y gh`) that must finish in ~5 min.
  • Pre-fill via URL params — `?prompt=...&repositories=owner/repo&environment=...` to wire up a 'send to Claude Code' button from an issue tracker.

How to use it (first run):

1. Go to claude.ai/code, sign in, and install the Claude GitHub App, granting repo access (cloud sessions need an existing GitHub repo — make an empty one first for a new project).

2. Create an environment — leave defaults (`Trusted` network, no setup script) for a first project.

3. Pick a repo + branch, choose a permission mode (defaults to *Auto accept edits*; switch to *Plan* to approve first).

4. Describe the task specifically and press Enter — e.g. `Add a README with setup instructions` or `Fix the failing auth test in tests/test_auth.py`. Name files/functions and paste error output.

5. Review the diff (`+42 -18` indicator), leave inline comments on specific lines (queued and bundled with your next message), then Create PR (full, draft, or GitHub compose). Session stays live after the PR to handle CI/review feedback.

Terminal shortcut: if you use the `gh` CLI, run `/web-setup` inside Claude Code (needs CLI ≥ v2.1.80, claude.ai login) to sync your GitHub token and auto-create a default environment — no browser flow needed.

Breaking changes:

  • None — it's an additive new surface, not a change to the existing CLI. Caveats: cloud sessions only offer *Auto accept edits* and *Plan* modes (no Ask/Bypass), don't use your local config (repo only), require GitHub (or a `--remote` bundle), and orgs with Zero Data Retention can't use cloud session features.
  • Note: the official docs don't currently embed a demo GIF/video, so none is included here rather than linking a fabricated one.

Links:

  • Launch it: claude.ai/code

Why it matters for you: Kick off and review changes to your GitHub Pages + Supabase projects from anywhere—including your phone—and run multiple experiments in parallel without ever cloning locally, which is exactly how you stay ahead of the curve.
