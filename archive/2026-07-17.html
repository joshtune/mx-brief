Claude Code + Clay Makes Lead Generation Actually Fun

38.4K

Claude Code orchestrates Clay to source, enrich, and pitch leads.

It's a concrete, reproducible pattern for wiring Claude Code to an external B2B data API and driving a full outreach workflow in natural language — no new UI to learn.

details

What it is: A lead-gen pipeline where Claude Code is the orchestrator and Clay is the data source — one prompt sources leads, enriches them, and writes personalized cold outreach.

How it works:

  • Setup: Create a Clay account, connect it to Claude Code. Claude Code reads Clay's API endpoints and figures out how to call them — you just describe your ideal customer ("avatar") in plain English.
  • Source: Prompt Claude Code ("get me 50 leads that look like X, Y, Z"). It reaches out to Clay, scrapes the lead list, and pulls back initial leads.
  • Enrich: Clay enriches each lead — company data, emails, phone numbers — via its waterfall enrichment: it hits its top provider, and if there's no match, cascades down to provider 2, 3, etc. Clay resells negotiated access to many B2B data providers, so you bring your API keys and pay per credit instead of stacking subscriptions.
  • Personalize: Enriched data flows back to Claude Code, which writes the cold email copy. Critical prereq: you must feed Claude Code context files first — Nate loads a business profile, case studies, FAQs, proof/offer docs, and website copy. Without that, the copy reads generic and spammy.
  • Output: A CSV of leads + enrichment + personalized subject lines and bodies.
  • Launch: Upload the CSV back into Clay, buy domains, warm them up, and start the campaign — all from inside Clay.

The two problems it solves:

  • Data problem (finding real businesses + valid contact info) → Clay
  • Tool problem (too many UIs and tabs to juggle) → Claude Code as a single natural-language front end

Tools & links:

  • Claude Code — the orchestrator; calls Clay's API, manages context files, writes outreach copy
  • Clay — B2B data + waterfall enrichment source (affiliate link, 2,000 free credits)
  • AI Automation Society (free resources) — Nate's community
  • $1M AI agency playbook — his growth optin

Why it matters for you: This is the exact "Claude Code as orchestrator over an external API" pattern — it shows how to let the model discover and drive third-party endpoints from context files, which generalizes far beyond lead gen.

Pydantic AI 2.0: The New Best Way to Build AI Agents is Composing Capabilities

22.8K

Pydantic AI 2.0 makes 'capabilities' the core agent primitive.

Cole reframes agent-building as composing reusable Lego-like bricks — a mental model you can steal for structuring mx-workflow's skills, hooks, and tools instead of piling them loosely onto agents.

details

What it is: A breakdown of Pydantic AI 2.0's new `capability` primitive — a self-contained unit bundling instructions, tools, lifecycle hooks, and model settings into one composable brick.

How it works:

  • A capability packages everything an agent responsibility needs: tools (its arm to the outside world), instructions, guardrails, lifecycle hooks, and model settings — in a single input to the agent definition.
  • An agent is now just a set of composable capabilities combined together, rather than an "unorganized pile of tools, instructions, and guardrails."
  • Capabilities are reusable across agents — piece them together like Lego blocks and share between your personal/business agents.
  • Think of capabilities as the layer above MCP servers: MCP packages tools for sharing; a capability wraps an MCP server *plus* the instructions, settings, hooks, and human-interaction/injection logic around it. MCP is a subset of what a capability holds.
  • Nothing underneath is new — hooks, skills, guardrails, sub-agents, MCP servers are things you already use (especially in coding assistants). The win is the *simplification* of pulling them into one framework primitive.
  • Positions Pydantic AI back in the lead after it fell behind the rise of coding-agent SDKs (Claude Agent SDK, Codex SDK), which are dead-simple for personal agents but slower and more token-heavy. Capabilities integrate cleanly with hooks, sub-agents, and MCP in just a couple lines.

What's different this time: Cole's angle is the *convergence* — the industry has been settling on the same components (hooks, guardrails, skills, MCP), and Pydantic AI 2.0 is the first to unify them under one composable abstraction instead of separate bolt-ons.

Tools & links:

  • Pydantic AI — the agent framework; 2.0 introduces the `capability` primitive
  • Pydantic AI GitHub — source and 2.0 release notes
  • Claude Agent SDK — the coding-agent SDK he contrasts against
  • OpenAI Codex SDK, LangChain, CrewAI — named as points of comparison (no repos cited in transcript)

Why it matters for you: The capability model is a clean template for structuring mx-workflow — bundle each agent's skill + hooks + tool permissions + model settings into one reusable unit rather than scattering them, so capabilities compose across your mx agents the same way Cole's do.

He Told 5 AIs: Make Money or Get Deleted

16.9K

Guy gave 5 AI models $1K each to trade stocks.

It's a cheap, replicable side experiment — spin up AI-managed brokerage portfolios and let the models compete for real returns.

details

What it is: A guest ran a live experiment giving five AI models $1,000 each of real money to trade stocks, framed as a winner-take-all competition where losers get their subscription canceled.

How it works:

  • Funded 5 separate portfolios in a Charles Schwab brokerage account: Claude, ChatGPT, Gemini, Grok, Perplexity — $1,000 each ($5,000 total).
  • Stakes were deliberate: $1K (not $20–50) so he'd take it seriously and the models would too.
  • Prompted each model that it's competing against the other four and he'd cancel the paid sub of any loser — "one winner" framing.
  • Key prompt hack: had to *repeatedly* push the models to give real, actionable trades instead of theoretical/hedged "this is not financial advice" recommendations. Told them explicitly: real money, okay to lose it all, be as risky as possible.
  • Grok complied immediately (loosest guardrails); Claude and ChatGPT resisted hardest on liability grounds.
  • He manually executes each model's picks in its named portfolio — the AI advises, he places the trades.
  • Reported results (his claims): Claude "more than doubled" / "30x'd" and led; Gemini started losing and turned into a "gambler."
  • Model rationale: Grok picked for X/Twitter firehose sentiment; Gemini for Google search data; Perplexity as a meta-model routing to others; ChatGPT/Claude as the base contenders.
  • Started late 2025, ~6 months in. Minimum ~$20/mo per model subscription.

Tools & links:

  • HighLevel — sponsor CRM, 30-day free trial (affiliate)
  • PlaymakersAI — his community for consultants charging $500–5k/mo on AI services
  • Charles Schwab — brokerage used to run the five portfolios
  • Models: Claude, ChatGPT, Gemini, Grok, Perplexity (~$20/mo each)
  • Note: a paid "step-by-step AI stock trading business plan" is teased in the description as the actual monetization play.

Why it matters for you: Low-lift, low-capital side experiment you can copy this weekend — the real edge is prompt engineering the model past its liability hedging into concrete trades, and the packaged "business plan" upsell shows the monetization angle beyond the trades themselves.

The creator seeding playbook

14.2K

Seed products to 1,000 creators, not run ads.

A concrete, working go-to-market playbook that replaces paid ads with an army of everyday creators pumping out volume content on commission.

details

What it is: A distribution strategy where brands "seed" product to ~1,000 ordinary creators who flood TikTok/Reels with volume content instead of paying for Facebook/Google ads.

How it works:

  • Skip paid ads (Facebook, Google) as the primary acquisition channel.
  • Recruit ~1,000 creators — not influencers or even micro-influencers, just "people with time on their hands" who've watched enough TikTok/Reels to know what content performs.
  • Each creator ships ~30–40 videos/month → ~5,000 pieces of content per month across the pool.
  • Most videos get zero views; a few pop off — it's a volume/lottery game, and the winners carry the ROI.
  • Motivate with a commission + tiered prize ladder. Golia's example structure:
  • $10K in sales → 15% commission
  • $100K → trip to Miami
  • $1M in a month → a condo in Miami + a Lamborghini

  • No specific tools or URLs named in the transcript — the mechanics are the product (TikTok, Reels) plus a creator affiliate/commission program.

Why it matters for you: If you ship a product, this is a repeatable, low-CAC playbook — turn distribution into an incentive-driven affiliate machine instead of a paid-ad line item.

The school kids love more than vacation

A school built on hard challenges kids crave.

A case study in engineering intrinsic motivation through high standards and hard, gamified challenges — the same lever that makes great products and teams sticky.

details

What it is: A short clip on a school model designed to be more compelling to students than vacation, built on high standards and physically/mentally hard "alpha tasks."

How it works:

  • Core thesis: you can't build something kids love more than vacation *if you have low standards* — the difficulty is the draw, not the deterrent.
  • Motivation hack: nothing drives a student harder than going head-to-head with their parent and winning.
  • Social pull: excitement comes from getting their friends to do hard things together.
  • "Alpha tasks": busy workshops you must complete and then *pass a gate* to clear the level (game-loop mechanics applied to learning).
  • Escalating physical challenges by grade:
  • 45-ft wall climb
  • 2nd graders run a 5K
  • 8th graders complete a Tough Mudder — and everyone has to cross the finish line at the same time (forced team cohesion, no one left behind).

Tools & links:

  • No repos, tools, or URLs named in this clip.

Why it matters for you: The featured play is a repeatable pattern — raise the bar, gamify the gate, make it social — to manufacture the kind of pull that most products, onboarding flows, and teams fail to create.

details

What changed:

  • `/fork` now copies your conversation into a new background session (its own row in `claude agents`) so you keep working; the old in-session subagent it launched is now `/subtask`

  • New session-wide WebSearch cap (default 200, `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`) and subagent-spawn cap (default 200, `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`, reset by `/clear`) to kill runaway loops
  • Long-running MCP tool calls (>2 min) auto-move to the background; tune via `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`
  • `claude auto-mode reset` restores default auto-mode config (confirmation prompt, `--yes` to skip)
  • Safety fix: plan mode no longer auto-runs file-modifying Bash (`touch`, `rm`) without a permission prompt
  • Fixes to `/ultrareview` (accepts `#123`/`PR 123`/pasted URLs, fetches remote branches, no longer skips billing confirmation after `/clear`), hooks (`continue:false` halts no longer dropped on tool failure), SIGTERM process-tree cleanup in print/SDK mode, and the spurious "File has not been read yet" edit error

Breaking changes:

  • `/fork`'s behavior changed: it now creates a background session instead of an in-session subagent — use `/subtask` for the old behavior
