details

What it is: Cole's argument that AI coding agents ship insecure code more often than they ship slow or undocumented code, and his fix: deterministic vulnerability gates (SonarQube) wired into Archon workflows so nothing reaches a PR without a scan.

What he's doing differently now:

  • Runs *every* coding workflow through Archon as the engine. Each process (plan, build, verify, ship) is one file of stitched nodes: agents plus scripts, executable in parallel.
  • Security is a deterministic node, not another Claude call. He explicitly rejects the 'obvious' fix of a second agent doing a security review as the primary control.
  • The gate runs *before* a PR opens or control returns to him. The agent must detect *and* iterate on findings, not just report them.
  • Partnered with Sonar, so expect SonarQube to be his default scanner going forward.

How the vulnerabilities get in (his taxonomy):

  • Direct code vulns — agent writes the SQL injection itself.
  • Dependency vulns — agent installs a package (or version) with a known CVE without checking.
  • Transitive vulns — the package is clean but a sub-dependency carries a CVE. Agents research the top level at best, never the chain.
  • CVE list is massive — no agent is going to reason over it from context. It has to be a tool lookup.

How the workflow works:

  • Archon node graph: coding agent → SonarQube scan (SAST + dependency/CVE check) → agent reads findings → fix loop → gate passes → PR opens.
  • Determinism comes from scripts, not prompts. The scanner either passes or it doesn't.
  • Agent still does all the work; the harness just refuses to hand back control until the gate is green.
