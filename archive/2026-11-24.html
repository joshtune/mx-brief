Anthropic Engineer Explains: How to Stop Hitting Claude's Token Limit

61.4K

Stop burning Claude limits: protect the prompt cache.

Nate turns a Claude Code engineer's caching rules into habits you can change today, starting with why switching from Opus to Haiku mid-session costs you more, not less.

details

What it is: Nate explains a Claude Code engineer's posts on prompt caching. Your usage limit usually drains because of habits that break the cache, not because you use Claude too much.

How it works:

  • Claude remembers nothing between messages. Every time you hit enter, the whole conversation gets sent again: instructions, tools, files and the full history. In a long session that's tens to hundreds of thousands of input tokens *per message*.
  • Nate's own logs: he ran 7 real tasks on Opus last month. Claude read about 160M tokens and wrote about 500K, roughly 200 tokens read for every one written. Reading is where your limit goes.
  • Prompt caching: Claude saves the part of the conversation it has already processed and only fully works through what's new. Cached input costs about 1/10 of the normal price, or less on some models.
  • Anthropic treats cache misses as an emergency: Thariq (Claude Code team, transcribed as "Thoric") says the whole tool is built around caching, with alarms when the cache starts missing too often. A high cache hit rate is what lets them offer more generous subscription limits.
  • Prefix matching: the cache is only reused if everything from the top of the conversation down stays exactly the same (settings, tools, instructions). Change one thing and everything after it is reprocessed at full price.
  • LEGO analogy: swap a brick near the bottom of the tower and you have to rebuild everything above it.

Habit #1: switching models mid-session

  • Scenario: you're 100K tokens into an Opus session and you switch to Haiku for an easy question to "save usage".
  • Each model keeps its own cache, so Haiku has to read all 100K tokens from scratch.
  • Result: the answer itself is cheaper, but re-reading the whole chat costs more than just letting Opus answer.
  • Caveat: Thariq posted this in April and the exact numbers shift with new models. Every model still keeps its own cache, so switching still means rebuilding it.

The fix:

  • Set everything up at the start of the session: model, tools, instructions, skills.
  • After that, only add new messages to the bottom.
  • Don't build or edit skills, tools or instructions mid-session. Nate is starting on this point when the transcript cuts off.

Gap: the transcript ends after habit #1, so habits #2 and #3 aren't captured. Watch the video for them.

Practical moves (my inference, not from the video):

  • Want a cheaper model for a side task? Start a fresh session or hand it to a subagent instead of using `/model` in a long session.
  • Lock down CLAUDE.md, MCP servers and skills *before* starting long sessions.
  • Same rule for API pipelines: put the stable system prompt and tool definitions first and anything that changes per request last.

Tools & links:

  • Claude Code: the agentic CLI the caching advice is about
  • Anthropic prompt caching docs: how cache prefixes and cached-input pricing work
  • Free AI OS Template: Nate's free template (email opt-in)
  • AI Automation Society Plus: Nate's paid Skool community

Why it matters for you: if you work in Claude Code all day, keeping the cache intact stretches your weekly limit further than downgrading models, and the same prefix rule cuts costs in any Claude API pipeline you build.
