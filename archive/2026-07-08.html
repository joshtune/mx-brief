The Best AI Coding Setup Isn't the Most Autonomous One (Here's Why)

Five levels of AI coding autonomy, mapped to self-driving.

Cole argues Level 3 (delegate-and-validate), not the fully autonomous 'dark factory,' is the sweet spot — a direct lens for tuning how much you trust your mx-workflow agents.

details

What it is: A breakdown of Dan Shapiro's five levels of AI coding autonomy, mapped onto the 2013 SAE five levels of driving automation — from 'spicy autocomplete' to the fully autonomous 'dark factory.'

How it works:

  • Level 0 — Spicy autocomplete: You write every line; the agent is a smarter Stack Overflow. Never has the final say.
  • Level 1 — Coding intern (cruise control): Agent writes boilerplate — repo setup, package installs, unit tests, simple refactors. Nothing that needs real reasoning.
  • Level 2 — Junior developer (highway autopilot): Heavy pair programming; agent runs autonomously in easy situations but you drive manually for anything with real rules/turns. Cole says most viewers are stuck here and should push past it.
  • Level 3 — Developer (where Cole operates): You build a real system for planning → implementing → validating, then delegate *all* coding to the agent. Cole hasn't written a line of code himself in over a year. Trust comes from the system, not blind faith.
  • Level 4/5 — Dark factory (full autonomy): Fully hands-off pipelines. Cole has built one himself but warns of significant downsides — powerful, but not where most should aim.
  • Key insight: The right level changes over time as your structured approach matures; most people self-assess higher than they actually are.

Tools & links:

  • Referenced tools: Claude Code, OpenAI Codex
  • No specific repos linked in this transcript excerpt (thought-leadership piece, not a build walkthrough)

Why it matters for you: The plan→implement→validate loop is exactly what elevates mx-workflow from Level 2 (you babysitting each task) to Level 3 (agents own the code, you own the validation gates) — invest in the validation harness, not just more autonomy.

Finally, an Open Standard for the Karpathy LLM Wiki is HERE

48.5K

Google's Open Knowledge Format standardizes Karpathy's LLM wiki pattern.

If you're building agent-readable knowledge bases, OKF is a shareable markdown standard worth adopting into mx-workflow before you lock into a bespoke wiki structure.

details

What it is: Google's Open Knowledge Format (OKF) — an open standard that formalizes Andrej Karpathy's viral "LLM wiki" pattern into plain, interlinked markdown any agent can read with zero integration (no plugin, RAG pipeline, or vector DB).

The backstory:

  • Karpathy released the LLM wiki idea a couple months back — a pattern for building a personal knowledge base / "second brain" using an LLM to incrementally build and maintain a persistent, interlinked collection of markdown files.
  • The seed gist hit ~40k stars. It's so simple you can paste the file into a coding agent and it'll basically one-shot building you a wiki.
  • Key behavior: instead of dumping docs or indexing for RAG, the LLM reads each new source (meeting transcripts, plan docs, articles), extracts key info, and integrates it into existing entity pages — building a traversable knowledge graph the agent can walk.

The problem OKF solves:

  • Everyone building their own LLM wiki structures it differently. No standard = no way to share your wiki with a teammate, because their agent doesn't know your metadata/entity conventions and can't search it optimally.
  • Use cases: one shared team wiki that everyone's second brain queries independently; a creator sharing a curated knowledge base with their audience.

How OKF works — two things it standardizes:

  • Information organization — how entity documents and concepts are structured, plus categorization so the agent can traverse the wiki like a knowledge graph.
  • Metadata fields — the exact fields tagged at the top of every document (title, tags, categorization) so agents can query by title/tags across any OKF wiki.
  • Index file — every wiki has a top-level index the agent maintains on each ingest and reads first on nearly every search; gives a high-level overview (article + quick summary) so the agent knows what's worth opening.
  • Migrating an existing Karpathy-style wiki into OKF is described as very easy.

Cole's framing:

  • Even if you never share your wiki, OKF is worth it purely as an optimization layer on top of Karpathy's idea.
  • Google is losing the model race (Gemini < GPT/Claude) but is shipping strong work on *leveraging* LLMs effectively — a different lane than building them. Even if OKF isn't THE final standard, something like it will win, so learn it now.

Tools & links:

  • Open Knowledge Format (OKF) — Google's open markdown standard for LLM wikis (search "Open Knowledge Format" / Google's OKF spec repo; exact URL not stated in transcript)
  • Andrej Karpathy's LLM wiki gist — the ~40k-star seed pattern (github.com gist, exact URL not given in transcript)

Why it matters for you: This is Cole's current thinking on structured, agent-native memory — directly applicable to mx-workflow: adopt an OKF-style index + metadata + entity-page convention for your knowledge/context files so agents traverse them as a graph and the format stays portable across tools instead of a bespoke one-off.
