  • Anthropic deleted over 80% of the Claude Code system prompt for the Opus 5 release.
  • Every model launch, they delete/rewrite system prompt chunks, swap the tool set, and rewrite tool descriptions. Prompts do not transfer across model generations.
  • Reason given: most of the old system prompt was *correcting for behaviors the model should have known*. Opus 5 already does those things — so the corrections are now noise.

  • The term for it: unhobbling the model — removing constraints rather than adding them.

Nate's experiment:

  • He'd been feeling Opus 5 as *degraded* — falling back to 4.8 for some tasks and getting better results.
  • Realization: the degradation may be his own instruction stack fighting a smarter model, not the model.
  • Method: duplicated his repo, stripped out CLAUDE.md and all skills, ran it clean, compared.

The mental model he uses:

  • Instructing a 10-year-old on a slide deck → be maximally prescriptive (10 slides, exact titles, colors, text formatting). Zero freedom, because stakes are high and competence is low.
  • Instructing a 10-year veteran who's made hundreds of decks → the same instruction set *gets in their way* and blocks their subject-matter expertise.
  • Opus 5 is the veteran. Your CLAUDE.md is still talking to the 10-year-old.

Practical takeaways:

  • Treat every model release as a different personality — different flaws, strengths, and prompting style. Re-audit skills on each drop.

Your AI Second Brain Is Slowly Rotting (Here's How to Fix It)

8.9K

Second brains decay — engineer staleness detection into memory.

If your agent memory files are append-only, you're accumulating contradictions that actively degrade agent output — and this is the maintenance layer nobody's guide covers.

details

What it is: A problem-first breakdown of *memory decay* in AI second brains — why append-only knowledge bases rot, and how to engineer detection + pruning instead of just adding more storage.

What Cole is doing different:

  • Everyone else's second-brain content stops at *architecture* (core docs + daily logs + knowledge graph). Cole starts where they stop: maintenance.
  • He's been running his own second brain for 6+ months — long enough that decay is observed, not theoretical.
  • Frames decay as an *engineering* problem with a designed solution, not a "just re-read your notes" discipline problem.

The standard second-brain shape (his framing):

  • Core behavior + memory docs — `memory.md`, `soul.md`, always loaded into context. Concise by necessity.
  • Daily logs — append-only running record of what you did.
  • Karpathy-style LLM wiki — knowledge graph of entities and concepts across your life/business.

Why it rots:

  • Duplicity is structural, not a bug. Core memory needs the concise version; the knowledge graph needs the detailed version. Same facts, two representations — they drift apart.
  • Contradictions are the actual killer. When the agent pulls a wiki doc that disagrees with `memory.md`, it doesn't error — it gets confused and produces worse output than having no memory at all.
  • Your life changes faster than your files. Stale entities/concepts get retrieved with full confidence. A memory that was true in January is now a lie the agent asserts.
  • Intra-graph drift too — two entities describing the same thing in different words, neither wrong, both incomplete.
  • Sources multiply the problem: conversations, email, calendar, client-call transcripts, inbound leads, project docs, codebases — dozens of inbound streams, zero outbound pruning.

The fix (his thesis):

  • Build stale-detection into the second brain itself — the system should flag contradictions and outdated entities, then update or delete them.
  • Treat it as a solved-by-design problem: he claims it's "quite easy to implement" once you stop treating the knowledge base as write-only.

Tools & links:

  • Hermes — open-source downloadable second brain, referenced as one of the "install in a couple hours" repos *(exact repo URL not stated in transcript — search "Hermes second brain GitHub")*
  • Open Claw — same category, open-source second-brain scaffold *(exact repo URL not stated in transcript)*
  • Granola — AI meeting notepad; sponsor, but relevant as a transcript source feeding a second brain
  • Archon — Cole's own agent-orchestration / harness-engineering project, the usual home for these patterns
  • Karpathy's LLM wiki pattern — entity/concept knowledge graph as agent-readable markdown

How mx-workflow should improve from this:

  • Your `CLAUDE.md` + `.claude/` context files are a second brain, and they're append-only right now. Same rot applies.
  • Add an `/mx:memory-audit` command — scan `CLAUDE.md`, context-primed files, and any memory docs for: (a) references to files/commands/ports that no longer exist, (b) two docs asserting different things about the same subsystem, (c) entries whose last-touched date is far behind the code they describe.
  • Timestamp every memory write. `/mx:context-prime` should stamp created/updated dates so staleness is computable, not vibes.
  • Make `/mx:context-clean` smarter than delete. Right now it removes context files; give it a *reconcile* mode that diffs the context file against current code and rewrites the drifted claims.
  • Contradiction check as a review gate. You already have `mx:hallucination-check` for invented APIs — the sibling is a *stale-context check*: does the guidance in CLAUDE.md still match the repo?
  • Single source of truth per fact. If a fact lives in both `CLAUDE.md` and a local context file, one should point at the other rather than restate it. Cole's duplicity problem is exactly what a plugin with layered context files invites.

Why it matters for you: You're building a workflow plugin whose entire value is persistent, reusable project context — and this video is the argument that context you never prune eventually makes the agent worse than a cold start.

Fork subagents by default, @-mention sessions, security fixes.

Two workflow-changing defaults land here — forked subagents that inherit your full conversation and prompt cache, and `@`-mentioning another live session to hand it work directly.

details

What changed:

  • Subagent forking is on by default — a `subagent_type: "fork"` subagent inherits your full conversation *and* prompt cache, so spawned agents start with everything you've already established instead of a cold context
  • Non-teammate agent spawns in interactive sessions now run in the background by default — you keep working while they churn
  • `@` in the prompt mentions another Claude session by name, and Claude uses `SendMessage` to reach that session directly
  • `SendMessage` resolves bare names — if exactly one live session matches, it delivers instead of asking you to confirm a ref
  • Unique session names per machine — starting or renaming into a name already taken gives you a `name-word-word` variant and tells you
  • New `/config` rows: "Dialog expiry" and "Messages from your other sessions" (cross-session inbound accept / hold / refuse)
  • GitLab parity: secret redaction for the `glrt-`/`gloas-`/`glptt-`/`glagent-`/`glimt-`/`glsoat-`/`glcbt-`/`glft-`/`glffct-` token families, full redaction of routable `glpat-`/`gldt-` tokens, and `glab` CLI config gets the same sandbox + credential-path protection as `gh`
  • GitLab plugin marketplaces: bare `gitlab.com` repo URLs (incl. nested subgroups) clone like `github.com` URLs; auth-failure hints now name your actual git host
  • Friendlier settings aliases: `additionalMarketplaces` → `extraKnownMarketplaces`, `allowedMarketplaces` → `strictKnownMarketplaces`
  • Fable 5 is back in `/advisor` for orgs with Fable access, consent via `/model fable`

Security fixes:

  • PowerShell permission bypass — variable-writing parameters could silently overwrite `$PSDefaultParameterValues` and redirect later commands' file access
  • Windows permission bypass — Git Bash followed Cygwin-style symlinks that path validation read as regular files; writes through them now require approval
  • Nested git repos no longer inherit trust from a parent directory — each repo now needs its own trust confirmation
  • Remote Control sessions hosted by a bridge inside a cloud session no longer inherit that session's transcript or credentials

Other fixes:

  • MCP connections no longer hang the full 30s connect timeout when a server fails to answer or malforms the protocol-version probe

Breaking changes:

  • Nested git repositories no longer inherit parent trust — if you work in a repo-inside-a-repo layout, expect a fresh trust prompt per repository
  • Behavioral default flip: subagent forking on by default and background-by-default spawns change how agent output reaches you mid-session
  • Gateway (enterprise): stricter boot validation — unknown or invalid `desktop:` overlay keys now *fail boot* instead of being ignored; empty `managed.policies[].match.groups` / `admin.admin_groups` entries and malformed `email_domain` values (empty, or containing `@`, whitespace, or commas) also fail boot rather than silently matching no one or granting admin
