How to Actually Run Your Coding Agent Safely (And Avoid the Horror Stories)

2.1K

Sandbox your YOLO-mode coding agent with Docker.

If you run Claude Code with `--dangerously-skip-permissions` (you do), this shows the Docker sandbox setup that keeps a bad agent decision from wiping your filesystem, DB, or SSH keys.

details

What it is: A guide to running coding agents in full YOLO/auto-approve mode *safely* by isolating them inside Docker sandboxes instead of on your bare machine. Cole partnered with Docker on this one.

The core argument:

  • Every agent (Claude Code, Codex, Cursor) ships a skip-permissions mode — `claude --dangerously-skip-permissions`. You're using it daily.
  • The fix is NOT to stop using YOLO mode. Approving hundreds of actions kills autonomy and wastes your time.
  • The fix is to give the agent full autonomy inside an isolated environment where a mistake can't hurt the host.

The risks he enumerates (each maps to an isolation layer):

  • Filesystem — un-sandboxed agent can read/edit/delete any file or folder on your machine. Assume no real protection.
  • Processes & environment — it can kill processes, edit env vars, tear down apps. Common failure: agent hits a port conflict and kills your running apps to "fix" it.
  • Docker engine — needs its own engine so it manages its own containers, not destroying containers for your other running services.
  • Network — needs an allow-list of outbound URLs. Without it, a prompt-injection attack can grab an API key and exfiltrate it to an attacker's URL.

How the solution works:

  • Docker sandbox = isolated VM/container environment for the agent to work in.
  • Multiple graded levels of isolation (filesystem, process, own Docker engine, network allow-list) — Docker's docs lay these out as distinct tiers.
  • Chosen because it's free, easy to set up, and capable.
  • Real horror stories referenced: Claude Code / Cursor / Codex wiping databases and deleting directories.

Tools & links:

  • Docker Sandboxes — free isolated environments for running coding agents; the docs diagram drives the whole video's isolation model
  • Claude Code `--dangerously-skip-permissions` (YOLO mode) — the flag this whole video is about defanging

Why it matters for you: Your mx-workflow pipeline runs agents autonomously — before you point auto-approve agents at real repos/DBs, wrap them in a Docker sandbox with a network allow-list so a prompt injection or a bad `rm` can't touch the host; this is a concrete guardrail pattern to bake into the workflow.
