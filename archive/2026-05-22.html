How Claude prompt caching saves tokens and session limits.

If you're burning Claude Code sessions, understanding the 80/20 of prompt caching is the cheapest perf win you'll get this week.

details

What it is: A practical breakdown of how Claude's prompt caching works in Claude Code (and the API), why your sessions burn out, and how to keep your cache hit rate high so you stretch session limits further.

The core numbers:

  • Cached tokens cost 10% of normal input — a 10x discount on anything reused
  • Nate's dashboard shows 91M tokens cached in one day (billed like ~9M) and 300M+ in a week
  • Claude Code (subscription) cache TTL: 1 hour — idle longer than that and the whole session un-caches
  • Claude API / sub-agents cache TTL: 5 minutes by default, optionally bumpable to 1 hour (more expensive)

How caching actually layers (per Thoric @ Anthropic):

  • Globally cached: base system instructions; built-in tools (Read, Write, Bash, Grep, Glob)
  • Per-project cached: `CLAUDE.md`, project memory
  • Per-session: session state
  • Grows each turn: user messages
  • Matching is prefix-based — anything before the first change stays cached; anything after gets reprocessed

Cache create vs cache read:

  • Cache create = first-time write to cache. One-time cost, pays off on the next turn
  • Cache read = reused tokens (your CLAUDE.md, system prompt, prior turns) at 10% price
  • Turn 1 of a fresh session = no cache, everything is fresh input + cache write
  • Turn 2+ = the prefix gets read from cache, only the new delta is fresh

Why Anthropic cares (and you should too):

  • Thoric: Anthropic runs alerts on cache hit rate and declares SEVs if it's too low
  • High hit rate → Claude Code feels faster, serving cost drops, subscription limits feel more generous, long sessions stay practical
  • Low hit rate → lose-lose: slower, more expensive, sessions burn out

Practical takeaways:

  • Don't let sessions sit idle >1 hour if you plan to keep using them — you'll pay full freight on the next message
  • Keep `CLAUDE.md` and project context stable across turns (it gets cached per project)
  • Editing things early in the prompt invalidates everything after — keep volatile stuff at the end

Tools & links:

  • Anthropic prompt caching deep-dive (Thoric's article) — referenced in the video as the technical primer
  • Token dashboard (free) — Nate's giveaway, tracks input/output/cache create/cache read daily
  • AI Automation Society Plus (paid) — full courses + support

Why it matters for you: You're already using Claude Code daily — this is a no-code-change win. Knowing the 1-hour TTL and prefix-matching rules means you stop accidentally torching your session limits, and Nate's free token dashboard gives you the visibility to actually see it working.

Counter to the "just go be an entrepreneur tomorrow" advice — 90% of startups fail.
  • Cut your bottom 20% every year. Goldman fires the bottom 20% annually. Every high performer does a quieter version of this. Apply it to your own life: clients draining energy, morning habits that aren't moving the needle, people in your circle capping your ceiling. Audit annually and prune.
  • Be honest when you're failing — especially publicly. The expensive mistake isn't the bad trade; it's spinning a story around the gap instead of closing it. People respect "I'm failing at this, here's why, here's the fix" more than the house-of-cards performance of looking successful.

The OPX framework (steal this): Before any major move, ask three questions —

  • Whose capital can I use instead of mine?
  • Whose resources can I use instead of mine?
  • Whose network can I use instead of mine?

If the answer to all three is "my own," you're thinking about it wrong. OPX = Other People's X (money, contacts, infrastructure, credibility).
