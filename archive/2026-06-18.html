Every Level of a Claude Second Brain Explained

28.7K

Five levels of building an AI second brain.

It's a concrete blueprint for structuring your own knowledge as plain markdown files that any AI agent (Claude Code, Codex, custom harnesses) can actually recall instead of hallucinate.

details

What it is: A walkthrough of five maturity levels for a file-based AI "second brain" — folders of markdown that agents can search and recall, demoed on Nate's real "Herku" project.

The core principle:

  • Your moat is your data/IP — the hard part is *organizing* it so an agent can find it again, not just dumping it.
  • Work backwards / reverse-engineer from the question: how you'll recall data later determines how you store it now (his basketball-hoop-and-ball analogy — design the input to fit the retrieval).
  • Litmus test: *can your agent (and you) find it again?* If no, your routing/folder architecture is wrong.
  • It's model-agnostic — "just files and folders," so it works across Claude Code, OpenAI Codex, and his own Hermes agent harness.

The five levels (retrieval capability ladder):

  • Level 1 — Exact match: find a file/info by searching an exact word or name.
  • Level 2 — Topic aggregation: pull everything on a given topic together.
  • Level 3 — Semantic search: search by *meaning*, so different words than you wrote still surface the right info.
  • Level 4 — Relationship chains: trace topic X back through the chain all the way to topic A (the "relationship mapping" / clustered-node graph shown visually).
  • Level 5 — Autonomous: the second brain ingests, routes, and recalls on its own — knows your business, you, and your relationships well enough to out-remember you.

How it works in practice:

  • It's literally folders of markdown files organized so both Nate and his agents understand the structure.
  • Inputs: notes, meeting recordings, ClickUp threads — saved, then ingested and routed to the right spots.
  • He demos two projects: his real production "Herku" brain, plus a from-scratch project to show what scaling from level 2→3 looks like.

Tools & links (from the video):

  • Free AI OS Course (Skool) — his free AI Automation Society group/course
  • AI Automation Society Plus (Skool) — paid, full courses + support
  • Claude Code, OpenAI Codex, and his "Hermes" agent harness — used as interchangeable front-ends to the same file-based brain (no repo linked in transcript)

Why it matters for you: It's a tool-agnostic mental model for engineering a retrieval-first knowledge base — the level ladder tells you exactly what folder/routing architecture to build before reaching for embeddings or a fancy agent.

details

What it is: A sponsored (NordVPN) myth-busting explainer on whether personal VPNs still matter in 2026.

How it works:

  • Distinguishes personal VPNs (NordVPN) from corporate VPNs — only the former is in scope.
  • A VPN forms an encrypted tunnel to a VPN server, so the internet sees the provider's network, not yours — it changes the network you appear to be on.
  • Tackles the big anti-VPN argument: HTTPS (TLS) already encrypts traffic, so the payload is hidden either way.

The Creators of Claude Code and OpenClaw don't Prompt Their Agents Anymore?!

5.8K

Loop engineering: agents that prompt themselves while you step away.

Boris (Claude Code lead) doesn't prompt Claude anymore — he writes loops, and Cole breaks down the exact Claude Code primitives (/loop, /goal, /routines, the loop skill) you can wire into your own agent workflow today.

details

What it is: A practical, skeptic's take on "loop engineering" — building self-prompting agent loops instead of hand-prompting every step — using Claude Code's native primitives.

The thesis the big players are pushing:

  • Boris Cherney (lead on Claude Code): *"I don't prompt Claude anymore. I write loops and the loops do the work. My job is to write loops."*
  • Peter Steinberger (creator of OpenClaw / open claw): runs the same self-prompting style — but Cole's caveat is Peter has a near-infinite token budget.
  • Cole's honest stance: it's a buzzword that barely deserves its own term, loops are unreliable and extremely token-hungry, so don't adopt blindly.

How loops actually work (the Claude Code primitives):

  • `/loop` — set an interval to re-run a prompt. Claude wakes itself every N minutes (e.g. every 5 min: "check this repo for new GitHub issues and handle any that come in"). Runs autonomously as long as the terminal/Claude Code session stays up; polls an external system (GitHub) for input.
  • `/goal` — define done-criteria, then force the agent to work until it's met. Same spirit as the viral "Ralph loops." Also exists in Codex.
  • `/routines` — scheduled jobs (e.g. every hour: wake up, read a larger spec doc, do the next task).
  • The loop skill — built into Claude Code: tell the orchestrator agent "use the loop skill" + hand it a spec doc, and it sets up the whole loop system for you. Each cycle does the first unchecked task → validates → marks done → next cycle picks up the next task.

The architecture Cole advocates:

  • One orchestrator agent you talk to with minimal, high-level prompting; it figures out the loop and spawns workers.
  • Feed work as an incremental spec/checklist — never let an agent swallow too much at once or it gets overwhelmed.
  • Build a system to observe loops/orchestrators/workers, and optimize cost by routing to cheaper providers (he name-drops "Pi") — i.e. treat it as harness engineering for long-running tasks, with eyes-open trade-offs.

Tools & links:

  • Claude Code — `/loop`, `/goal`, `/routines`, and the loop skill are the building blocks discussed
  • OpenClaw — Peter Steinberger's agent project (referenced as a loop-engineering exemplar)
  • Codex — noted as also having a `/goal`-style done-until-complete mode
  • Pi — alternate/cheaper model provider for cost-optimizing workers (no URL given in transcript)

Why it matters for you: This is a direct blueprint for leveling up mx-workflow — wrap your existing agents in a `/loop` + loop-skill orchestrator that chews a spec checklist incrementally, add observability over orchestrator/workers, and route cheap tasks to a budget provider so the token-hunger doesn't bankrupt you.

What it is: A profile of David Rubenstein, co-founder of The Carlyle Group, framed as an atypical private-equity operator who built influence first and fortune second.

Who he is:

  • Co-founder of The Carlyle Group, one of the largest PE firms in the world
  • Started in the Washington DC area, not Wall Street — politics, not finance, was his first network

How he made money / built leverage:

  • Ran off-the-record convenings: assembled subject-matter experts on topics Congress was actively debating
  • Invited congressmen, senators, and staffers from both parties to these closed-door sessions
  • This positioned him at the center of DC's information flow — relationships and access that translated directly into Carlyle's deal flow and fundraising power
  • Carlyle famously leaned on government/defense-adjacent expertise and political relationships as a competitive edge

The 'patriotic philanthropy' play:

  • After getting wealthy, he stepped in when the Washington Monument was cracking (cement failing on the centuries-old structure)
  • Congress was 'paralyzed and incompetent,' so he personally funded the repair — guilting/shaming legislators into action
  • Extended this to restoring other national monuments — branding himself as a civic benefactor, which compounded his reputation and access

The pattern to steal:

  • Build a neutral, high-value convening platform before you need anything from it
  • Own the relationships and the information, and the money follows
  • Use visible generosity as reputation infrastructure, not just charity
