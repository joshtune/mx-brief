V — Verify the output:

  • The core distinction, credited to Goldman CIO Marco Argenti: a model's *reasoning* can be useful even when its *final answer* is wrong. Mine the breakdown, verify the result.
  • Verification starts upstream, at the data. Every BI analyst in Nate's role had to pass an internal "data school" — how data gets pulled, cleaned, updated, and turned into something decision-grade.
  • The punchline on data quality: bad data plugged into AI "just gives you the wrong answer faster." Your proprietary data (customers, sales history, internal processes, support tickets) is the moat — but only if it's clean.
  • Verification prompt he actually uses: *"Before you give me the final answer, recheck every number and factual claim. Cite the source for each one, and flag anything you're not fully 100% confident about."*
  • Spot-check triage: don't verify every word. In a report, usually only 2–3 numbers could actually change the decision. Force citations on those, check those yourself.
  • Escalation for high stakes: spin up a separate AI reviewer — or a team of reviewer agents — that check the first output and let the system iterate *before* a human sees anything. But: important claims still need original sources, deterministic tests, or human review. AI review is an additional layer, not the last one.
  • Explicitly framed as tool-agnostic — applies whether you're on Claude Code, Codex, or whatever ships next month.

A — Augment, don't replace:

  • Nate's actual Goldman job was building automations, reports, dashboards, and internal efficiency systems — none of it branded as an "AI initiative." Goldman had been running automated data and risk systems for decades.
  • The takeaway: there was already a huge backlog of problems worth solving *before* agents existed. Hours-long manual reports, data shuffled between systems, teams blocked waiting on other teams, fat-fingered entries, skipped steps, two people running the same process two different ways.
  • The target isn't replacing the human — it's the inconsistency. Humans get tired, miss steps, drift from the process. That's the surface area automation should attack first.

How it works:

  • Take stock, not salary. Musk draws no cash salary from Tesla. Compensation comes as equity, so there's no W-2 income to tax.

The mechanics behind it:

  • Wage income is taxed the moment it's earned, at the highest ordinary rates. Asset appreciation is taxed only on realization — and possibly never.
  • Debt is not income. That single line is what makes the whole structure work.
  • Step-up in basis (IRC §1014) is the piece that converts "deferred forever" into "forgiven."
  • The scaled-down version: this is exactly why real estate and cash-flowing businesses beat a paycheck. Depreciation, refinancing (cash-out refi is the small-scale securities loan), and holding through death follow the same three-step logic.

Permissions UI, transcript perf fixes, background session reliability.

Two things directly change your daily driving: a startup warning that your `Bash(git * main)`-style allow rules are looser than you think, and a new Auto mode tab in `/permissions` so you can actually see and edit what auto mode is allowed to do.

details

What changed:

  • Permissions get visible. New Auto mode tab in `/permissions` for viewing and editing auto mode classifier rules — the thing that was previously a black box.
  • Wildcard allow-rule warning. Startup now flags Bash allow rules with a wildcard *before* the subcommand (e.g. `Bash(git * main)`), because they also match options injected before the subcommand. Worth auditing your `settings.json` allowlist today.
  • Turn timing. End-of-turn duration line now includes completion time: `✻ Sautéed for 23s · done 6:05 PM`.
  • Transcript perf: severe slowdown fixed when a diff contained one very long line (base64, minified bundles) — those now render truncated with a marker.
  • Fullscreen fixes: blank transcript after terminal resize, erratic scrolling from an earlier message, jump-to-bottom getting stuck mid-transcript.
  • Background sessions: no more 45s failure-to-open when the starting dir was deleted / machine slept / host slow; no more `EACCES "Couldn't start the background service"` when another Claude Code process was mid-npm-reinstall.
  • `claude agents`: fixed stopping a just-booting session ("was stopped while the respawn was in flight", common on Windows) and duplicate rows for a backgrounded named session — repeats now number as `my-session (2)`.
  • Worktree safety: the background retention sweep no longer deletes git worktrees under `.claude/worktrees/` that *you* created when a stale session record pointed at them.
  • MCP correctness: interrupted tool calls in headless/remote sessions now report an explicit interrupted error instead of lying with "completed with no output"; args for empty-schema (`{}`) params are sent as their real type instead of JSON strings.
  • Auto mode on big sessions: safety-check deadline now scales with prompt size, so tool calls stop getting denied as "temporarily unavailable".
  • Markdown rendering: no longer disabled for a whole message when the first 500 chars look plain; `+` and `N)` lists and setext headings now render.
  • Workflows: pressing ← or running `/background` during a dynamic workflow no longer silently restarts finished subagents — it asks first and tells you how many would restart.
  • Plugins: duplicate SHA-named cache dirs, doubled `/plugin:plugin:skill` prefixes, `claude plugin update <bare-name>` failing, and install failing on a UTF-8 BOM in `plugin.json` — all fixed.

Breaking changes:

  • None outright, but the wildcard allow-rule warning is behavior-visible: rules like `Bash(git * main)` now surface a startup warning. They still work — you're being told they match more than you intended.
  • MCP servers relying on the old empty-schema behavior will now receive real typed values instead of JSON strings; if you wrote a server that `JSON.parse`d those args, fix it.
