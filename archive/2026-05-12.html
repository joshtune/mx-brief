Multi-Agent Building In Claude Code Somehow Got Easier

20.7K

Claude Code's new agent view manages parallel sessions in one tab.

If you're juggling multiple Claude Code sessions across terminal tabs, this new built-in view replaces that mess with a single dashboard — exactly the kind of workflow upgrade Nate surfaces fast.

details

What it is: A walkthrough of Claude Code's newly-released agent view — a single terminal tab that lets you spawn, monitor, and switch between parallel Claude Code sessions, plus the new `/goal` command for Ralph-Wiggum-style autonomous loops.

How it works:

  • Press left arrow inside any Claude Code session to open agent view (the central dashboard)
  • Press right arrow to drop into a specific session; left arrow returns to dashboard
  • Sessions are color-coded: yellow = needs input (e.g. plan approval), green = completed, others = working
  • Type a task description directly into the agent view input and hit enter — it spawns a brand-new session with that prompt, no separate terminal needed
  • `/bg` inside an active session backgrounds it into the agent view
  • `claude --bg "<task name>"` launches a new backgrounded session from the shell
  • `claude agents` is the alternate launch command, but Nate says left-arrow is faster
  • Each session ends with a built-in recap summarizing what it worked on — helps when you're context-switching across many

The `/goal` command (new):

  • Mirrors the goal feature in Codex — a continuous experimentation loop (Ralph Wiggum style)
  • `/goal build me a 3D monster fighting game` and Claude Code keeps iterating, trying approaches, until the objective is hit
  • Tracks elapsed time on the goal in the UI

Four patterns Anthropic highlights:

  • Scaling concurrent sessions
  • Managing long-running agents
  • Coordinating work that needs human approval gates
  • Goal-directed autonomous loops via `/goal`

Tools & links:

  • Claude Code — the CLI this whole video is about (use the terminal version, not the VS Code extension, for full functionality)
  • AI Automation Society Plus (paid Skool) — Nate's paid community + courses
  • AI Automation Society (free Skool) — free resources
  • Nate's YT Podcast application
  • Uppit AI — Nate's agency

Why it matters for you: You're already running Claude Code with multiple agents — agent view + `/goal` collapse the terminal-tab chaos into one keystroke (left arrow) and give you a sanctioned autonomous-loop primitive without rolling your own.

What it is: A rapid-fire rundown of six business types with unusually high survival rates — the "steal their homework" list for aspiring side-hustle owners.

The six businesses:

  • Rental properties — 85.3% success rate. Simple business, hard assets. Carnegie's line: 90% of millionaires got there through real estate.
  • Laundromats — 95% success rate over 5 years. Recession-proof, low complexity.
  • Self-storage — 92% success rate. A leading asset class since 2008.
  • Transportation businesses — 90% success rate. Riding the Amazon/last-mile logistics wave.
  • Vending machine routes — Low entry cost ($3K–$5K). Catch: hard to scale.
  • Senior care centers — 97% success rate. Government grants, tax breaks, and city allowances subsidize entry. Expensive to get into, but the moat is real.

The pattern:

  • Hard assets or recurring demand
  • Boring enough that smart money ignores them
  • Either low-capital entry (vending) or subsidized entry (senior care)
  • Survive recessions because the underlying need doesn't go away

claude-code

v2.1.139

Agent view, /goal command, transcript nav, hook upgrades.

Two new commands (`claude agents`, `/goal`) directly change how you drive long-running Claude Code sessions day-to-day.

details

What changed:

  • Agent view (Research Preview): `claude agents` lists every session — running, blocked on you, or done. See docs
  • `/goal` command: set a completion condition and Claude keeps working across turns until it's met. Works in interactive, `-p`, and Remote Control. Live overlay shows elapsed/turns/tokens
  • `/scroll-speed`: tune mouse wheel scroll speed with live preview
  • `claude plugin details <name>`: show a plugin's component inventory and projected per-session token cost
  • Transcript navigation: `?` for shortcuts, `{`/`}` to jump between user prompts, `v` to toggle shortcut panel
  • Hook `args: string[]` (exec form): spawns command directly without a shell — path placeholders no longer need quoting
  • Hook `continueOnBlock` for `PostToolUse`: feed hook's rejection reason back to Claude and continue the turn
  • MCP stdio servers now receive `CLAUDE_PROJECT_DIR` (matches hooks); plugin configs can reference `${CLAUDE_PROJECT_DIR}`
  • Compaction prompt now preserves sensitive user instructions
  • `/mcp` Reconnect picks up `.mcp.json` edits without restart; shows HTTP status + URL on failure
  • `/context all` per-skill token estimates now use the model's tokenizer
  • `claude plugin install <name>@<marketplace>` auto-refreshes the marketplace and retries before failing
  • Subagent API requests carry `x-claude-code-agent-id` / `x-claude-code-parent-agent-id` headers; OTEL spans include matching attributes

Breaking changes:

  • Remote Control, `/schedule`, claude.ai MCP connectors, and notification preferences are disabled when `ANTHROPIC_API_KEY` / `apiKeyHelper` / `ANTHROPIC_AUTH_TOKEN` is set — even if a Claude.ai login also exists. Unset the API key to restore these features
  • Hooks now run without terminal access (fixes prompt corruption but means hooks can't write to terminal anymore)
  • HTTP/SSE MCP response bodies capped at 16 MB per SSE frame

Fixes:

  • Deadlock where expired credentials + `forceRemoteSettingsRefresh` blocked `claude auth login`/`logout`/`status`
  • `autoAllowBashIfSandboxed` now handles `$VAR` and `$(cmd)` expansions
  • `Skill(name *)` wildcard now works as prefix match

Links:

  • Release notes
  • Agent view docs

Why it matters for you: `/goal` lets you hand Claude Code a finish-line condition instead of babysitting turns — exactly the leverage upgrade for daily-driver use. Check whether you have `ANTHROPIC_API_KEY` set; if so, `/schedule` and Remote Control just stopped working until you unset it.
