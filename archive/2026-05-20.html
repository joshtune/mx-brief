What it is: A 5-minute walkthrough on mirroring a Claude Code project's config so Codex can read the same context — no duplication, no lost work.

The core problem:

  • Claude Code looks for `CLAUDE.md` + `.claude/` folder
  • Codex looks for `AGENTS.md` + `.codex/` folder (plus an `agents/` folder for skills)
  • Same shared knowledge (docs, references, scripts), different filenames per agent

How it works — the mirror:

  • Instructions file: `CLAUDE.md` ↔ `AGENTS.md` (Codex injects `AGENTS.md` at session start the same way Claude injects `CLAUDE.md`). Content is essentially identical — copy it over.
  • Config folder: `.claude/` ↔ `.codex/` — holds agent memory, agents, rules, skills, settings
  • Skills folder: Claude's skills live under `.claude/skills/`; Codex puts skills in a top-level `agents/` folder
  • Skill files are portable: markdown + YAML frontmatter format is identical across both tools — drop-in compatible
  • Agent files differ slightly: Claude uses markdown; Codex uses its own file format, but they do the same job
  • Global vs project scope works the same way: both support `~/.claude` / global Codex equivalents for user-level rules, plus project-level overrides

The shortcut:

  • Nate teases a prompt you can paste into either agent to auto-convert a project between the two layouts (since both agents can read their own docs and figure out what's missing). Transcript cuts before he shows the prompt itself.
