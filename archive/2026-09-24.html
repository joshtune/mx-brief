AI Coding Rate Limits are RIDICULOUS Now - Here's How You Keep Scaling Anyway

9.7K

Beat rate limits by mixing cheap and premium models per workflow step.

Cole proves you can match top-tier LLM output quality while burning way fewer tokens, just by matching model cost to the specific step (plan/implement/validate/review) — directly applicable to how mx-workflow's agent pipeline allocates models.

details

What it is: Cole hit hard rate limits on both his $200/mo Claude Code Max plan and $200/mo Codex Pro plan mid-week, with days left before reset — a trend he says the whole industry is now hitting as coding agents scale up token usage. His response: stop treating "which LLM" as a single choice and instead strategize model selection *per step* of the coding workflow.

How it works:

  • Core workflow steps: planning → implementing → validating → reviewing.
  • Key finding: the planning step is the highest-leverage step — a well-written plan lets even a smaller/cheaper model implement it and get nearly identical results to using the top model end-to-end.
  • Rule of thumb: use the most capable model for planning and reviewing, use a smaller/cheaper/faster model for implementation (implementation is the most token-heavy part of the cycle, so this is where savings matter most).
  • He validated this using his AI Software Factory — an autonomous system he's built and covered in prior videos that takes a scope of work and builds + validates code end-to-end with no human in the loop. He used it to build the same test app (a small video game) three times, swapping model combos:
  • Open models: DeepSeek V4.1 Flash (planning + reviewing) + GLM 5.3 Flash (implementation)
  • Claude: Fable 5.1, max effort (planning + reviewing) + smaller Claude model for implementation
  • Codex: GPT6 Astra, max effort (planning + reviewing) + smaller model for implementation
  • Result: all three combos produced comparable output quality to using the top model for every step — confirming the plan-step-is-king thesis and that implementer model choice matters far less than expected.
  • He picked "best of group" models by checking live open-model leaderboards (DeepSeek V4.1 Flash currently tops the open-model tag).

Tools & links:

  • No repo URLs were given in this transcript excerpt (AI Software Factory referenced as his own system from prior videos on his channel, no link provided here).

Why it matters for you: mx-workflow's pipeline already splits work into plan/build/test/review agents (mx-plan, mx-implement, mx-test-builder, mx-quality-keeper, etc.) — Cole's data suggests you could deliberately route cheaper/faster models to the implementer and heavier-lift agents while reserving your best model for mx-plan and review-stage agents, cutting token burn without a quality hit.
