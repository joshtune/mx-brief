I Made My AI Agents Faster Without a GPU Upgrade

LMCache vs vLLM's cache for faster coding agents

It's mostly a software-caching video, not a hardware shootout, so skim it for the machines he used and skip the rest. The transcript gives no prices and no Mac mini comparison.

What it is: A benchmark of KV-cache strategies for multi-turn coding agents, run on expensive GPU boxes. The fix for slow agents is caching, not a bigger GPU.

Machines he uses (the part you care about):

  • NVIDIA RTX Pro 6000 — the single-GPU demo. One agent's time-to-first-word grows from ~0.12s on turn 1 to ~19s on turn 25 with no cache.
  • NVIDIA DGX Station GB300 — the main test rig, running Qwen3 235B on a 32K-token document.
  • RTX 5090 (32 GB) — mentioned only as a warning: a 32 GB model won't leave room for cache on it.
  • Apple M5 Ultra — appears only in the description ("needs something from you before it really pulls ahead"). The transcript is cut off before it shows up.
  • Cost vs Mac mini: not in the available transcript. Any numbers would be invented, so check the full video or the gear links in the description.

How it works:

  • KV cache is the model's "notes" on your prompt. Without it, the model rereads the whole history every turn.
  • No cache: a 30-turn session rereads ~115K tokens by the end, over 2M tokens in total.
  • vLLM prefix cache: it never reads more than ~10K tokens a turn, about 14x less. It's on by default, and it keeps the notes in GPU memory.
  • vLLM CPU offload: the notes spill into system RAM, still inside the vLLM process.
  • LMCache: a separate server outside vLLM that keeps notes in RAM and sometimes on NVMe SSDs. The cache survives a vLLM crash or a reboot.
  • GB300 result: no cache took ~1.35s. Any of the three cache options took ~112–122ms, roughly 11–12x faster.
  • Memory tradeoff: the notes compete with the model for VRAM. When VRAM fills, the oldest notes get evicted and the model rereads everything.

Tools & links:

  • LMCache — external KV-cache layer for vLLM, with RAM and NVMe tiers
  • vLLM — open-source LLM server with built-in prefix caching and CPU offload
  • Incogni — the sponsor, a data-broker removal service; skip it
