Telling Claude Code 'make it better' 100 times

It's a quick, concrete test of what happens when you loop an agent on a vague prompt, with the exact prompt and model settings shown, so you can see the failure mode before you burn 8 hours of tokens on it.

What it is: An experiment where Nate fed Claude Code a deliberately awful coffee shop website and sent the same "make it better" prompt 100 times in a row, once with Sonnet 5.5 and once with Opus 5.5, both on medium effort.

How it works:

  • Starting point: One intentionally bad coffee shop site, given to both models.
  • Exact prompt, sent 100x: "Look at the site first, then innovate. Make one bold change that improves conversions or the look and feel, not a small tweak. Use any tool you have. You must ship a change every time."
  • Runtime: Opus ran about 8.5 hours. Sonnet ran almost 2 hours.
  • Code size: Opus ended at about 21,000 lines of code. Sonnet ended under 3,000.
  • Opus result: Pure AI slop. Falling leaves, a changed background, walls of text, a pumpkin-carving widget (small knife or big knife), and a Spanish toggle that doesn't translate anything.
  • Why it broke: "You must ship a change every time" plus "bold change, not a small tweak" forces the model to keep adding. It had no stopping condition and no vision, so it piled on features until the site broke.
  • Biggest surprise: Neither model used the internet. With "use any tool you have" in the prompt, neither did any research, look up references or pull in design inspiration.
  • His takeaway: The model sets the ceiling, and the prompt sets the direction. "Innovate" with no vision turns into adding.

Tools & links:

  • Claude Code — the agent running the loop (no URL given in the video)
  • Sonnet 5.5 and Opus 5.5, both at medium effort — the two models compared

Why it matters for you: Don't loop an agent on a vague, must-ship prompt. Give it a goal, a reference or vision, and a stop condition, and tell it to research first, or you get 21k lines of bloat. The video has no step-by-step build, so it's less instructive than Nate's usual videos.
