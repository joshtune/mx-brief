Cole's skill for building a personal AI news filter

Cole turned his six-month-old content engine into a 'grill-me-first' skill, which is a pattern you can copy into mx-workflow for building personalized, interview-driven skills.

What it is: A walkthrough of Cole's 'AI content engine' (part of his second brain) and the free `Build Signal Engine` skill that has your coding agent build the same system for you.

How it works:

  • Skill instead of repo. He ships a skill, not a clone-and-run repo, so you customize while it builds. Six months of lessons learned are baked into the skill.
  • Grill-me intake. The skill interviews you first: which sources to track, how to fetch them, what you care about, and how to filter. It builds only after that.
  • Data layer first. You connect sources before any filtering. His sources: Reddit, YouTube, RSS, Hacker News, GitHub repos, arXiv, and changelogs such as Claude Code's.
  • Per-source connector choice. Each platform can use an API, a CLI, or an MCP server. The skill asks which you want.
  • Apify for locked-down platforms. His newer addition. It is one platform that connects agents to thousands of sources (YouTube, Reddit) where official APIs are restricted.
  • Daily run, dedupe first. Everything is pulled daily, then deduplicated against a central database that tracks what has already been announced, before any processing or filtering.
  • Filter by personal relevance. The filter knows what he cares about (his content, his AI coding workflows) and outputs one concise daily digest. It is not a full news roundup, and he has tuned its accuracy over time.
  • Gap in this summary. The transcript cuts off at the dedupe step, so the filtering, scoring and digest internals are not covered here. Watch the rest of the video for those.

Tools & links:

  • Apify — one platform for scraping and connecting agents to YouTube, Reddit and other restricted sources
  • Cole's main skills GitHub repo, which holds the `Build Signal Engine` skill — the exact URL isn't in the transcript, so check the video description
  • Claude Code changelogs, Hacker News, arXiv, Reddit, RSS, GitHub — the sources he feeds in

Why it matters for you:

  • Interview-first skills. Add a 'grill me' phase to mx-workflow skills such as `/mx:build` or `/mx:prd`, so they collect preferences before generating anything. mx:prd already works this way.
  • Teach-the-build skills. Ship skills that scaffold a customizable system instead of a fixed one, and encode hard-won lessons in them.
  • Pluggable connectors. Offer API, CLI, MCP or Apify choices per source rather than hardcoding one. Your own mx-brief pipeline would benefit from Apify for X and YouTube.
  • Dedupe stage. Run an explicit dedupe stage ahead of any LLM filtering. You already do this with `seen_items.json`, so this confirms the design.
  • Personal relevance filter. Score items against a stored profile of interests instead of summarizing everything. That would sharpen the per-channel reader focus in this brief.
