Pydantic AI 2.0: The New Best Way to Build AI Agents is Composing Capabilities

Cole Medin · 2026-07-10 · 20,304 views  ·  Watch on YouTube →
Pydantic AI 2.0 makes 'capabilities' the core agent primitive.

Cole reframes agent-building as composing reusable Lego-like bricks — a mental model you can steal for structuring mx-workflow's skills, hooks, and tools instead of piling them loosely onto agents.

What it is: A breakdown of Pydantic AI 2.0's new `capability` primitive — a self-contained unit bundling instructions, tools, lifecycle hooks, and model settings into one composable brick.

How it works:

  • A capability packages everything an agent responsibility needs: tools (its arm to the outside world), instructions, guardrails, lifecycle hooks, and model settings — in a single input to the agent definition.
  • An agent is now just a set of composable capabilities combined together, rather than an "unorganized pile of tools, instructions, and guardrails."
  • Capabilities are reusable across agents — piece them together like Lego blocks and share between your personal/business agents.
  • Think of capabilities as the layer above MCP servers: MCP packages tools for sharing; a capability wraps an MCP server *plus* the instructions, settings, hooks, and human-interaction/injection logic around it. MCP is a subset of what a capability holds.
  • Nothing underneath is new — hooks, skills, guardrails, sub-agents, MCP servers are things you already use (especially in coding assistants). The win is the *simplification* of pulling them into one framework primitive.
  • Positions Pydantic AI back in the lead after it fell behind the rise of coding-agent SDKs (Claude Agent SDK, Codex SDK), which are dead-simple for personal agents but slower and more token-heavy. Capabilities integrate cleanly with hooks, sub-agents, and MCP in just a couple lines.

What's different this time: Cole's angle is the *convergence* — the industry has been settling on the same components (hooks, guardrails, skills, MCP), and Pydantic AI 2.0 is the first to unify them under one composable abstraction instead of separate bolt-ons.
