I Made Codex and Claude Code Build the Same App. One Clearly Won.

Nate Herk | AI Automation · 2026-08-14 · 101,488 views  ·  Watch on YouTube →
Codex vs Claude Code building the same Typeform clone.

Nate runs an identical multi-phase agent prompt through both coding agents and shows the real cost/time spread ($800 vs $3,000, 5 hours vs 3 days) plus where each one's output actually breaks.

What it is: A head-to-head bake-off — one prompt, two coding agents (Codex and Claude Code), same brief: build a production-ready, originally-branded Typeform alternative.

The setup:

  • Single identical prompt fired into both agents via a `/goal` slash command
  • Prompt structure: orchestrate specialized agents across three phases — research → build → verify
  • Closing instruction was the important part: *"do not stop at a prototype or first successful build. Continue researching, building, testing, breaking, fixing, and retesting until the app is genuinely complete."*
  • Nate's own retro on the prompt: he'd insert a planning/flow-mapping phase between research and build next time, and thinks both outputs would improve materially
  • One run was kicked off on his Mac while traveling; the second was an afterthought — not a controlled lab, more a real-world A/B

The headline numbers (from the intro):

  • Time: one finished in ~5 hours, the other took 3 days
  • Cost: one burned ~$800, the other ~$3,000
  • Nate withholds which-is-which early on and blurs the signup page to avoid tipping the reveal

First output walkthrough ("RealForm"):

  • Marketing site: hero image, depth/background treatment, feature pill, sections for Experience / Reliability / Pricing, dual CTAs ("build a private draft" + "start building")
  • Nate's read: clearly AI-generated to a trained eye, but *"an average person probably wouldn't look at this and assume vibecoded"*
  • Signup page landed well — clean vibe
  • No API keys provisioned, so auth is stubbed: you land in a demo workspace instead of a real account
  • Form builder: welcome screen editing, inline text with variable insertion (score, price), element sizing controls, button label editing, image upload

Where it cracks:

  • Deletion is unclear — no obvious way to remove individual elements; the visible delete action nukes the entire form
  • UI overload — Nate calls the builder "a little bit overwhelming... a lot going on"
  • Image upload silently fails — accepts the file, then renders "image preview is unavailable"
  • Takeaway: the verify phase ran, but agents don't think to test the scenarios a real operator would hit
