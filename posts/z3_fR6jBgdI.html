M6 vs M5 MacBook Pro: is $400 more worth it?

It tells you what the extra $400 for an M6 MacBook Pro over an M5 buys in hardware, but this part has no local-AI benchmarks and no Mac mini prices, so skim the numbers and skip the video.

What it is: Alex runs the same developer tests on the M5 and M6 MacBook Pro to see if the M6's $400 premium is worth paying.

The machines:

  • M5 MacBook Pro: 10 cores. 4 "super" cores (Apple's fastest) and 6 efficiency cores. Base storage is 512GB.
  • M6 MacBook Pro: 12 cores. Only 2 super cores, plus 4 new performance cores and 6 efficiency cores. Base storage is 1TB, so part of the $400 pays for twice the storage.
  • Same chassis: no redesign. The open question is whether the hotter M6 throttles sooner. He teases that test but it isn't in this part of the video.
  • Mac mini reference: he tested the M6 in a Mac mini a few weeks earlier. The M6 MacBook Pro beat that mini's JS score. He gives no mini price.

Scoreboard (M6 vs M5):

  • JS browser test (React, jQuery, charting; runs on one core): 78.4 vs 69, about 14% faster. Highest score he's recorded, Mac mini M6 included.
  • C++ sort of 100M numbers, one core (same seed on both machines): 5.14s vs 5.37s, about 4%. Not much.
  • Xcode clean build (iOS app with 76 open-source libraries): 118s vs 144.9s, about 23% faster. That saves about 27 seconds on every clean build.
  • C++ sort, all cores: 24% faster.
  • Takeaway: one fast core barely improved, but using all cores is about 23–24% faster. The 6 "good" cores beat the 4 "best" ones when the whole chip is working.

Who should care:

  • Anything that compiles (Xcode, Rust, Go, .NET) gets the big gain.
  • Mostly single-threaded work (editor, Node event loop, Python scripts) feels about the same.
  • Coming from an M1–M4? A refurbished M5 is the value pick unless you compile all day.
