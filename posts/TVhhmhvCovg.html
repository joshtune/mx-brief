Let Your AI Agent Do ITS OWN Harness Engineering (Here's How)

Cole Medin · 2026-10-20 · 24,090 views  ·  Watch on YouTube →
Agents fix their own rules and skills from traces

Cole turns harness engineering, which you now do by hand, into a loop where the agent reads its own failures and proposes fixes to its rules, skills and memory. That is the upgrade path for mx-workflow's skills.

Caveat: The transcript I had cuts off during the intro, before the live demo and the two learning loops are shown. Everything below is what he states up front. Watch the video for the actual loop mechanics.

What it is: A sponsored (LangChain) walkthrough of applying coding-agent harness engineering to production agents, with the agent helping improve its own harness.

What he's doing differently:

  • Harness engineering reframed: Track the mistakes your agent makes in production, then go back and talk through what to change in rules and skills so they don't repeat. You already do this for coding agents; he says it carries over to production agents unchanged.
  • Markdown replaces plumbing: Older agents put logic in Python/TypeScript tool functions. Now the harness is mostly markdown: skills, global rules (instructions .md) and memories. He says it's the same setup as a coding agent.
  • One-to-one mapping (his framing):
  • Rules = system prompt
  • Sub-agents = multi-agent workflows / delegation
  • MCP = connections / tools
  • Skills = workflows that replace many traditional tools
  • Hooks = guardrails (monitor or block on each tool call, or at conversation start/end)
  • Two improvement loops:
  • Loop 1: the agent's own main memory.
  • Loop 2: retroactive improvement from traces of the agent talking to real users. He calls this the biggest gold mine that most people ignore.
  • Automatic suggestions: The tracing/metrics platform surfaces where the agent goes wrong and offers suggestions you can apply automatically. He covers this later in the video.

Tools & links:

  • LangChain Managed Deep Agents — deploys agents in the coding-agent style, bundling markdown skills and rules for production. His pick for the demos.
  • LangSmith — tracing and metrics, and the source of the auto-applicable harness improvement suggestions.
  • mx-workflow — your project, the target for the takeaways below.
  • He says the ideas are platform-agnostic, and you can build your own deployment and harness-engineering pipeline.

How mx-workflow can borrow from it:

  • Add a postmortem loop: After a failed or corrected run, have a skill review the transcript. It should propose edits to specific skills, rules and memory files. This is the main idea worth stealing.
  • Log failures as traces: Keep a lightweight record of failures (corrections, rejected reviews, reverted commits) so the loop has data. Your mx:reject and mx:review verdicts are already a natural source.
  • Map your pieces to his taxonomy: Skills for workflows, agents for delegation, hooks for guardrails. Check which of your slash commands should be hooks, because guardrails that run on every tool call beat instructions the model may ignore.
  • Keep the harness in markdown: Prefer markdown over scripts wherever you can, so the agent can edit its own harness safely.
  • Gate changes: Auto-suggested edits should arrive as a reviewable diff or PR, not silent rewrites.

Why it matters for you: mx-workflow is a hand-tuned harness, and this video argues the next step is letting the agent read its own failures and propose the skill edits, with you approving them.
