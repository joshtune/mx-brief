Can Devin Actually Do Senior-Engineer-Level Work?

A Life Engineered · 2026-08-31 · 12,963 views  ·  Watch on YouTube →
Ex-Amazon principal interviews Devin against a senior-engineer bar.

Steve's message: the bar you'll be measured against is now the same rubric he's applying to an agent — craft, judgment, problem solving, communication — so learn to evaluate and direct agents instead of competing with them on output.

What it is: Steve Huynh (former Amazon principal engineer, bar raiser with ~1,000 interviews conducted) runs Devin through a mock senior-engineer interview on a real, broken vibe-coded project. Sponsored by Cognition; Steve states the rubric and scoring are his.

The rubric — memorize this, it's the transferable part:

  • Craft — quality of what it builds
  • Judgment — does it make the right calls
  • Problem solving — can it get through hard problems and obstacles
  • Communication — how well it reports back on what it did
  • Each dimension scored: *lowers the bar / meets the bar / raises the bar* → then a hypothetical hire/no-hire decision

The setup (the honest part):

  • Steve admits he fell into the vibe coding trap: a YouTube ideation/packaging/script tool built ~6 months ago with an AI harness
  • Kept adding features; each fix broke something else; he never read the code, so he couldn't vibe code his way out
  • App wouldn't even start. Code in GitHub, bugs and features seeded as a Linear project
  • Three goals: (1) deploy to a public endpoint + migrate local data to a remote DB, (2) Google OAuth, (3) connect to his YouTube channel for thumbnails and metrics

How Devin performed:

  • Setup: GitHub + Linear + Slack connected in under 60 seconds; sessions launchable from Linear, Slack, or the Devin web app — all three worked
  • Root-caused the dead app: the original code aggressively saved document versions *and* images into SQLite; the DB ballooned to 50 GB for a couple of documents, eating the laptop's free space and hanging the web server on startup
  • Filed a Linear issue for it, proposed a fix, wrote a script to extract the latest records — problem gone
  • Security judgment: Steve pasted private keys into chat; Devin *stopped him*, set up proper secrets handling, and invalidated the leaked keys
  • Suggested password-protecting the public site pre-launch; walked him through rotating the password when he claimed he forgot it
  • Migrated to a remote database unsupervised — no data lost — and switched database technology on its own judgment
  • Walked him through Google OAuth setup

Tools & links:

  • Devin (Cognition) — the AI software engineer under evaluation; sponsor
  • Steve's coaching program — promo-eligible, promised high performance review / promotion in a year
  • Linear, Slack, GitHub — the integration surface Devin plugs into (issues, chat, code)

What to prepare for:

  • Agents now clear the bar on *judgment*, not just code generation — blocking a secrets leak and choosing a different DB tech are staff-adjacent calls
  • The vibe coding trap is real and it has a cost curve: code you never read becomes code you can't fix, and the rescue requires "big boy engineering practices"
  • Your differentiator shifts to specifying work well (seeded Linear issues), reviewing agent output, and knowing enough architecture to sanity-check a DB migration you didn't watch

Why it matters for you: The four-dimension bar-raiser rubric is exactly what a senior engineer is judged on — watch to see which dimensions an agent already meets, because those are the ones you can no longer win on.
