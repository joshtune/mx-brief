Build A Custom Browser Extension [SUPER Easy!]

Matt Wolfe · 2026-07-13 · 14,645 views  ·  Watch on YouTube →
Vibe-coding a Chrome extension with GLM 5.2.

A single prompt gave Matt a working Chrome extension in 10 minutes — the same throwaway-tooling trick works for internal dev utilities around your web apps.

What it is: A speedrun of building a functional Chrome extension end-to-end with one prompt to an open-weight coding model.

How it works:

  • Prompted GLM 5.2 (from Z.ai) with a full spec in one shot: "Build me a Chrome extension called Page Brief — summarize the current page, extract action items, pull key links, copy everything as markdown, clean pop-up UI, generate all files."
  • Model emitted the complete file set (manifest, popup UI, scripts) ready to drop in.
  • Loaded it via Chrome → Manage Extensions → enable Developer Mode → Load Unpacked → select the folder.
  • Tested on an article: one click returned a summary, key takeaways, links, and a copy-as-markdown button.

Tools & links:

  • GLM 5.2 / Z.ai — open-weight, open-source coding model; pitched as much cheaper than closed models with comparable output (not sponsored, per Matt)
  • Chrome Extensions — Load Unpacked docs — dev-mode sideloading

Why it matters for you: Zero-friction path to disposable browser tooling — a scraper, a QA overlay, a JSON prettifier for your own web apps — built in minutes, and a cheap open-weight model worth benchmarking against your current coding LLM.

The caveats Matt skips: Load-unpacked extensions are trusting model-generated code with page-content access — review the manifest permissions before installing, and this is a demo, not production packaging (no store review, signing, or CSP hardening).

Depth check: Light. No code shown, no GLM setup walkthrough, no permissions discussion — it's a capability teaser, not a build tutorial.
