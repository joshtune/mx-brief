Shows the exact repo-to-cron pipeline for offloading Codex-built automations so they don't burn your subscription usage.

What it is: A workaround for Codex/Astra scheduled tasks eating your weekly usage limit — plan and build the automation inside Codex, then export it as code that runs independently on trigger.dev.

How it works:

  • Codex scheduled tasks send messages into a live chat thread, which consumes your actual Codex usage limit — bad for anything recurring.
  • Instead: use Codex/Astra to *plan and write* the automation as code, push that code to GitHub, and have trigger.dev execute it on its own infrastructure (zero Codex usage cost after the build).
  • Three automation types covered: (1) scheduled automation (cron-style, e.g. every 30 min or 6am Mondays), (2) webhook automation (event-triggered, e.g. form submission), (3) Codex SDK automation.
  • Demo walkthrough: a "morning routine" scheduled automation — fires 6am America/Chicago, reads Google Calendar events (descriptions, times, attendees, locations), decides which events need prep, and generates a daily brief.
  • Codex pulls context from existing project files (e.g. your current morning routine workflow) to inform how the automation should behave.
  • Code is written in TypeScript (trigger.dev's language) — Nate notes you don't need to understand TS yourself; Codex handles it. (Modal, mentioned as a contrast, would use Python instead.)
