Codex's Browser Agent Automates Literally Anything

Nate Herk | AI Automation · 2026-08-13 · 24,713 views  ·  Watch on YouTube →
Codex desktop's built-in browser agent for QA and automation

Codex's headed/headless browser agent gives you a persistent-login QA bot that clicks, types, and tries to break your app — Nate's demo ran 85 automated checks and surfaced real bugs, which is a straight upgrade over hand-testing five edge cases yourself.

What it is: A walkthrough of the browser-use agent baked into the Codex desktop app — driving a real browser side-by-side with the chat, for both UI QA and general "no API available" automation.

How it works:

  • Nate runs the Codex desktop app (his preferred way to drive Codex), which docks a live browser pane on the right-hand side of the chat.
  • Auth persists. Sign in to a site once inside the Codex browser and Codex saves the session — that's the unlock for automating tools that have no API.
  • Ordering of preference: use an API when one exists → check Codex's plugin library (Nate says "hundreds of plugins") → fall back to browser use only when there's no programmatic surface.
  • Annotate mode — click the annotate button, select a specific DOM element (he picks an overlapping phone-number field), and describe the fix in plain English. Annotations queue up in the chat and get fired off as a batch. Nate frames it as the Lovable / Claude-design-style visual editing loop, now inside Codex.
  • Shared control of the browser. You can drive the pane yourself (he Googles Grand Canyon images mid-demo); when Codex takes over, a distinct second cursor appears so you can tell whose mouse is whose.
  • The QA prompt he actually used, roughly: *"You have the UI open. I want to make sure there are no bugs and that this thing can't break. Use your browser use and test the heck out of it — try different things, try your best to break it, and let me know what bugs you find."*
  • What the agent does with that: clicks Continue on an empty form, reads back the validation errors (`First name is required`, `enter a valid email address`, `enter a 10-digit phone number`), fills plausible data, advances, and keeps walking the flow — validating that required fields actually block submission.
  • Headed vs headless — headed means the browser renders and you watch the cursor move; headless runs in the background so you keep working in the foreground. Nate's advice: ask for headless when you want it grinding for hours without hijacking your machine.
  • Scale claim: in his earlier "AI SaaS in one day" build, the same setup ran 85 focused automation checks with real click/type/submit workflows and surfaced a batch of bugs he then fixed.
