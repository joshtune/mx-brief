I Trust My AI Agents to Merge Code… But NOT Ship It

Cole Medin · 2026-11-13 · 1,446 views  ·  Watch on YouTube →
Sponsored pitch: feature-flag agents' PRs with LaunchDarkly

Mostly a LaunchDarkly ad, but the staging-gate-plus-flagged-canary idea is a cheap pattern to steal for mx-workflow's ship step; skip the video itself.

What it is: A sponsored short from Cole arguing that agents can merge code unattended, but production release needs a gated, flag-based rollout, pitching LaunchDarkly's new Release Autopilot.

How it works:

  • Cole's stance: his AI software factory stops at staging; he reviews there himself. Agent tests and reviews only prove the code *looks* right, not how it behaves with real users.
  • The old answer: wrap the change in a feature flag, release to a small group, watch it, kill-switch if it goes wrong. The catch is that a human had to add the flag by hand, so most teams never did it consistently, and it doesn't scale when agents open PRs in bulk.
  • Release Autopilot has agents do the flag work:
  • *Risk classification* decides how risky a change is and whether it needs a flag.
  • *Success metrics* are set up for how the change should perform in production.
  • *Automatic release plan* starts with a canary to a small subset of users and expands only while the change stays inside its guard rails.
  • *Feature-level observability* checks each change against live production signals.
  • *Flag cleanup* finds and removes stale flags from the codebase.
  • Human gate stays: the flag is proposed on the pull request, and nothing changes until someone approves it.
  • Takeaway: you don't have to trust the agent more. Every change is validated on real users before it goes to everyone.

Why it matters for you: For mx-workflow, steal the idea, not the product: make `/mx:shipit` and `/mx:release` stop at a staging or approval gate, and have the PR flow classify risk and propose a flag or rollout plan for human sign-off. A vendor-neutral equivalent would be a risk-tier check in `/mx:pr` and `/mx:review`.
