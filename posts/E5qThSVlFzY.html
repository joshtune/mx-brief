The Complete Local AI System with A Single NPM Install!

Cole Medin · 2026-07-31 · 6,113 views  ·  Watch on YouTube →
One npm install for four local AI models.

If you want a fully local, zero-API-key model layer under your agent tooling, this collapses four runtimes into one SDK import — but be clear that it's a sponsored spot, not a harness lesson.

What it is: A sponsored demo of QVAC, Tether's open-source local AI SDK, running speech-to-text, embeddings, an LLM, and text-to-speech from a single npm package.

What Cole is doing different here:

  • Normally a local stack means four separate runtimes and configs — Whisper for STT, Ollama for the LLM, something else for embeddings, something else for TTS. He replaces all of it with one import surface.
  • Models are pulled and run automatically on import — no per-service setup, no daemon babysitting.
  • His framing: models as *files on your machine* means no rate limits, no re-pricing, no deprecation out from under you. That's the argument, and it's the useful part.
  • Same API across every OS, so the stack is portable rather than machine-specific.

The demo pipeline (voice RAG assistant):

  • Whisper — transcribes the spoken question to text
  • Gemma — embedding model, retrieves matching notes (RAG step)
  • Qwen 3 — generates the answer
  • Supersonic — text-to-speech, reads the answer back
  • Question asked: "what is the database we ended up going with?" → answer: "We chose Postgres for reporting queries."
  • He explicitly says this is *not* optimized for latency — it's a breadth demo, not a production voice agent.

Claimed capability surface: LLMs, fine-tuning, RAG, image generation, video generation, transcription, STT, TTS — a dozen-plus capabilities out of the box.

Tools & links:

  • QVAC by Tether — the single-install local AI SDK; exact repo link was in the video description, not stated in the transcript
  • Whisper (OpenAI) — speech-to-text
  • Gemma — embeddings in this demo
  • Qwen 3 — the answering LLM
  • Supersonic — text-to-speech model used for playback

Honest caveat: This is a paid placement — he says so on camera and asks for GitHub stars. There's no harness engineering, no Archon, no agent-orchestration content here. Treat it as a tool signal, not a technique lesson.

Why it matters for you: For mx-workflow, the transferable idea is a single local-model dependency for the offline pieces — transcription, embedding-based retrieval over your own context files, and cheap local classification — so review/audit agents can run without burning API calls or leaking private repo content to a cloud endpoint; the QVAC-specific claims are worth verifying against the actual repo before you commit to it.
