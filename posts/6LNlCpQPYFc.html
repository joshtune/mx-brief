How to Actually Choose the Right AI Agent

Nate Herk | AI Automation · 2026-09-11 · 31,001 views  ·  Watch on YouTube →
Harness beats model: build portable agent IP, swap brains freely.

Nate and Mark Kashef lay out a concrete mental model for why your tools, skills, and context around the LLM matter more than which LLM you pick, which is exactly the framing you need before committing to Claude Code, Codex, Hermes, or a local stack.

What it is: In-person conversation (filmed at an AI event in Montenegro) between Nate Herk and Mark Kashef arguing that the *harness* around a model, not the model itself, is what makes agents useful, and that your loyalty should be to your harness and assets, never to a provider.

How it works:

  • The brain-in-a-jar diagram: the model is just the brain. Read, write/edit files, bash (creating/moving folders, controlling the machine) are limbs bolted on by the harness, not baked into the model.
  • The local-model test: ask a local model to "make me a website and spin it up locally" and it can emit the HTML but cannot start a server. That gap is the harness, not intelligence.
  • Claude chat vs Claude Code: same brain, different tools. Web Claude has a limited toolset; Claude Code has file system and shell access. Mark wishes it wasn't called "Code" because the name hides that the value is the tool layer.
  • Personality of harnesses: Claude Code described as the "wise old owl," Codex as the "Rottweiler" that obeys and keeps grinding until done. Different harness behaviors, not just different models.
  • The 70-80% local thesis: open-source models (Kimi named as an example) can already do ~80% of day-to-day work. Within the next year, run most tasks on local hardware and pull in frontier models only for genius-level planning.
  • Provider-agnostic rule: build skills, agents, context files, and workflows as your own IP so the model is interchangeable. "You can outsource the thinking but you can never outsource the understanding."
  • Skill decay: skills and agents rot fast. Mark cites Boris Cherny (Claude Code lead) tweeting that you should delete all your skills every six months. The reasoning is teased but falls after the transcript cutoff.
  • Tools in the noise: Hermes and a local tool called Pi come up as the community's current "should we switch?" questions. The answer given is to stop chasing tools and invest in the harness.

Caveats:

  • Transcript is truncated mid-sentence at the Claude chat vs Claude Code comparison, so the practical walkthrough, the Boris Cherny reasoning, and any hands-on demo are not captured here.

Why it matters for you: If you're building on Claude Code today, the actionable takeaway is to keep your skills, agents, and context files portable and provider-neutral, and to treat them as decaying assets you prune on a schedule.
