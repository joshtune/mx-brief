The Best Defense Against This Wave of AI Attacks: Hack Yourself First (Try This Now)

Cole Medin · 2026-11-26 · 4,318 views  ·  Watch on YouTube →
Hack your own app first with hunter-and-disprover agents.

Cole lays out a hunter-then-disprover agent pattern for security audits that you could add to mx-workflow as a review gate this week.

What it is: Cole argues that attackers now use AI to go from picking a target to privileged access in hours, so you should run the same AI attack workflow on your own app before you ship.

The threat picture (why now):

  • The FBI warned about a hacking agent that goes from target selection to full privileged access in under 3 hours
  • A researcher used a coding agent to find a critical Java vulnerability in about an hour
  • AI recently surfaced a PHP vulnerability that had gone unnoticed for years. AI lets attackers search wider and deeper than before
  • This video continues his security series. The previous episode covered attacks on *coding agents*. This one covers attacks on *the apps you build*

How attackers actually work (the pattern to copy):

  • Step 1: Hunter agent. One agent digs through the app and its source and flags *anything* that looks like an exploit, even at low confidence. The goal is breadth, because real exploits tend to be subtle
  • Step 2: Disprover agents. Each candidate gets its *own* agent, a separate session, subagent or background agent, playing devil's advocate. Its job is to prove the finding is not a real exploit
  • Step 3: Execute the survivors. Anything that can't be disproven gets a real exploit attempt to confirm it
  • The Java researcher followed this exact loop. The hunter produced mostly junk, the disprovers killed nearly all of it, and one confirmed finding remained
  • The idea: get high recall from the hunter, cut false positives with the disprovers, then require proof by execution

What's different vs. typical AI code review:

  • It is adversarial, not advisory. A finding is an allegation that must survive an attempt to disprove it
  • One agent per finding, so a single long context can't argue itself into or out of a result
  • Proof by execution is the bar, not "this looks risky"

Tools & links:

  • cloudflare/security-audit-skill: the Cloudflare skill Cloudflare demos. It runs a coding agent through the hunter → disprove → verify pipeline. MIT license. Install: `npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit`
  • Cloudflare blog: Build your own vulnerability harness: explains the design. It runs one hunter per attack class plus adversarial validators. The repo includes a JSON schema for reports and two dependency-free JS validators
  • Third-party breakdown (remio.ai): describes the skill's six-phase pipeline with independently verified, machine-readable findings
  • Caveat: a scanner rated a derivative copy Medium risk (skills.sh) because the skill tells the agent to execute code harnesses. Read SKILL.md before running it and sandbox it
  • Eney: the video's sponsor, a Mac/iPhone AI assistant with a 14-day free trial. Not related to the security content

How mx-workflow could steal this:

  • New `/mx:hack-yourself` (or `/mx:security-audit`) command: a hunter agent with a low confidence bar fans out to one disprover subagent per finding in parallel, and an executor writes a PoC only for findings that survive
  • Hunter per attack class: injection, authz/Supabase RLS bypass (this goes after the output of `mx-schema-builder`), SSRF, secrets in client bundles, Stripe webhook signature checks (relevant to `mx-shipkit-builder`)
  • Machine-readable verdicts: adopt a report JSON schema and validators like Cloudflare's, and have `/mx:reject` consume them so CI fails on any *confirmed* finding
  • Add a disprove pass to existing reviewers: `/mx:review` and `mx-silent-failure-hunter` could send each finding to a skeptic subagent before reporting, which cuts noise
  • Gate the build pipeline: run it in `/mx:build` after `mx-test-builder` and before `/mx:shipit`, and let `mx-quality-keeper` block on confirmed exploits
  • Run PoCs in isolation: use a git worktree or container so harness code never runs against your real env or secrets. This addresses the Medium-risk flag
  • Use `/mx:second-look` too: run the hunter on Cursor/Copilot/Claude Tag diffs, since AI-written code is exactly where subtle exploits hide

Why it matters for you: mx-workflow already has review agents. What it lacks is an adversarial, proof-by-execution security gate, and Cole's pattern plus Cloudflare's skill gives you a working reference to copy.
