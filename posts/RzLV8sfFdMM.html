What it is: A podcast interview with Cole Medin on treating Claude Code as a self-evolving "second brain" / AI OS — not just a coding tool — and how to be the *director* of your agents.

How it works:

  • Mind the "dumb zone": LLMs advertise huge context (1M tokens ≈ Harry Potter ×5), but quality degrades well before the limit. Cole pegs Opus's dumb zone at ~250k tokens — the big window gives a false sense of security. Keep context lean.
  • Plan more than you build: With coding agents, most of the work is planning. Front-loading the plan is what makes the agent effective.
  • Verification checks for quality: Without verification steps, first-pass quality sits around 65–70%. Add verification checks and you hit ~92% on the first pass.
  • Assume zero-trust on permissions: Telling an agent "never wipe the database" or "don't delete this folder" doesn't hold — it can write a script to do it anyway. Mindset: *anything the agent can read or touch, assume it will act on, even unprompted.*
  • Real incident cited: An over-proactive agent misread a task-list item and emailed their entire list a discount code that was never supposed to ship — concrete proof of why guardrails matter.
  • Beyond code: Cole uses Claude Code as a "second brain" to make a business AI-native (Nate's term: AIOS) — a system that evolves its own way of working over time.
