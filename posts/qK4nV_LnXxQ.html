Making An Actually Fun 3D Game with AI

Matt Wolfe · 2026-08-13 · 10,206 views  ·  Watch on YouTube →
Vibe coding a 3D roguelite sequel with Claude Code

Skip unless you want a reality check on how far AI coding agents get on a complex greenfield build — the planning discipline he applies transfers to web apps, the 3D game stuff doesn't.

What it is: Matt rebuilds his year-old vibe-coded game *The Librarian* as a 3D procedurally-generated roguelite using Claude Code (Opus 5) plus Codex, as a counter-argument to the "game dev is cooked" crowd on X.

How it works:

  • Original game: 2D library sim — students knock books off shelves, you re-shelve them for XP, a chaos meter hits 100% and you lose. Playable on GitHub.
  • The sequel's scope bump: 3D graphics, procedurally generated levels, new powerups, permanent meta-upgrades between runs, boss systems, and "disruptions" (sick kids, earthquakes that dump whole shelves).
  • Design goal is the roguelite "broken run" — occasionally stacking powerups until the character trivializes the game.
  • Two-model workflow: Claude Code with Opus 5 for the initial build (his pick for good-looking game output), Codex brought in as a second agent.
  • His actual thesis: the demos people post as proof of "AAA is dead" skip everything real studios do first — game director / creative director / design director roles, mood boards, concept art, color palettes, competitive analysis, character and story arcs. He and his producer did multiple planning sessions on game loop and character style before writing a line, and still admits to skipping narrative work.

Tools & links:

  • Claude Code — primary coding agent, Opus 5 model
  • Codex — second agent used alongside Claude Code
  • FutureTools — Matt's AI tool directory
  • The Librarian (v1) is linked from Matt's GitHub; the transcript snippet doesn't give the direct repo URL

Why it matters for you: The transferable lesson isn't 3D — it's that the multi-session planning pass (define the loop, the pillars, the constraints) before touching the agent is what separates a working build from a one-level demo, and that applies exactly the same to a web app spec.
