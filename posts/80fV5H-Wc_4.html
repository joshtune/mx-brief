Claude Code Just Silently Released a Cheaper Mode

Nate Herk | AI Automation · 2026-11-24 · 58,807 views  ·  Watch on YouTube →
Claude Code's code mode: fewer tokens, slower runs

Nate benchmarks code mode against normal Claude Code on four real jobs and gives the exact setup steps, so you can decide whether the token savings are worth the slowdown.

What it is: An experimental Claude Code setting where Claude writes one JavaScript program to make its tool calls, instead of calling tools one at a time. In Nate's tests it cut input tokens by about 35% and ran slower.

How it works:

  • Normal mode: Claude reads a file, reads the result, decides the next step, then calls the next tool. Everything it reads stays in the chat context for the rest of the session.
  • Code mode: Claude writes a short JS program that runs many calls in parallel and chains results. Only the final answer comes back into context.
  • You don't write or read the code. You prompt as usual. The name is misleading, since it isn't a mode for coding.
  • His analogy: normal mode sends an assistant to the filing cabinet one folder at a time. Code mode hands them a note saying "pull all 40 folders, total each customer, and come back with the top three."
  • Anthropic's own precedent: engineers tested this idea outside Claude Code about a year ago. An agent pulled a meeting transcript from Google Drive and attached it to a Salesforce lead. Writing code instead of calling tools directly dropped that job from 150,000 tokens to about 2,000.

How to turn it on:

  • Where it works: Claude Code in the terminal only. It doesn't work in the desktop app, the VS Code panel, or cloud sessions.
  • Version: 2.1.323 or later.
  • Account: a Claude subscription or a Console account.
  • Model: a current model such as Opus 5.5.
  • Switch: set the environment variable `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`. Set it in the terminal before launching `claude`, or put it in your settings file.
  • Lazy route (his usual): paste the code mode docs link into Claude Code and tell it to set this up.
  • First launch: a screen warns that Claude will write JS to call its tools and that the feature is experimental. Claude in Chrome and computer use are off while code mode is on. Pick "yes, turn on code mode" and a "code mode is on" line appears at the top.

His test setup:

  • Four small-business jobs:
  • Find the top 3 customers across 40 days of order files.
  • Find every broken link in a folder of 30 docs.
  • Change a phone number and a price across a 25-page website.
  • Ask one quick question about a single file.
  • Method: each job ran once with code mode off and once with it on, with the same model, effort and prompt. The orders job ran twice, which gives five comparisons.

Results (transcript cuts off before the full breakdown):

  • Accuracy: every run got the right answer in both modes, so code mode didn't make Claude smarter or dumber.
  • Tokens: fewer input tokens in all five comparisons, about 35% fewer overall.
  • Where the savings come from: mostly the fixed per-message overhead, not job execution. In his setup that overhead is about 60k tokens per message with code mode off and about 38k with it on, because the full tool list is swapped for a single code tool.
  • Speed: noticeably slower. He says this is the trade-off.
  • Not covered: the cutoff means we don't get his final take on when he'd use it in his own setup.
