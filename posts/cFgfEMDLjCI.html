Framework 13 Pro Ultimate Dev laptop

Alex Ziskind · 2026-08-23 · 33,648 views  ·  Watch on YouTube →
Framework 13 Linux laptop benchmarked against an M5 Max MacBook.

It's the clearest read yet on whether a modular x86 Linux box can stand in for Apple silicon as your dev machine — though Alex never puts it on an AI/LLM workload, so it tells you nothing about local inference.

What it is: A hands-on test of Framework's "ultimate developer laptop" claim — Linux daily-driving, modular expansion, pricing, and head-to-head dev benchmarks against a MacBook Pro M5 Max.

How it works:

  • Storage: Framework ships with a SanDisk SN7100 (PCIe Gen 4). Sequential read/write ~5800/5600 MB/s vs ~7100/7200 on the M5. Mac wins on paper.
  • The twist: random read/write — the thing that actually matters for `git clone`, `npm install`, opening projects — is *stronger* on the Framework, especially writes. Even the M5 Max doesn't come close.
  • Web Tooling Benchmark (clone repo → npm install → build → race), single-core JS/TS workloads:
  • Babel: 25.8 runs/sec Framework vs 34.18 MacBook
  • TypeScript: 31.6 Framework vs 46.65 MacBook
  • Geometric mean: 26.36 Framework vs 37.18 MacBook
  • Read: M5's single-core lead is real and sizable (~40% on the geomean). Framework is "somewhat there" — good enough for most dev tasks, not a performance win.
  • Modularity: expansion-card system is the actual differentiator — swap ports, including a 10G ethernet card, something no Mac offers at any price.
  • Verdict: Alex's own line — if he had an M5 MacBook Pro and needed a Linux machine, this is "an easy trade." Companion machine, not a replacement.

Tools & links:

  • WisdPi 10G Ethernet Expansion Card — 10 gigabit networking in a Framework expansion slot
  • Web Tooling Benchmark — V8's JS/TS toolchain benchmark (Babel, TypeScript, etc.); the "oldie but goodie" he runs
  • SanDisk SN7100 — the Gen 4 NVMe drive in his Framework config

Gaps for your purposes:

  • No dollar figures given in the transcript for either machine — no Framework-vs-Mac-mini cost comparison to extract.
  • Zero local LLM/inference testing. No model loads, no tokens/sec, no unified-memory-vs-discrete-GPU discussion. This is a JS/TS toolchain video wearing ML tags.

Why it matters for you: If you're sizing machines to run AI locally, this one doesn't answer the question — it's a Linux-dev-experience video, and the only durable takeaway is that random-write I/O on the Framework beats an M5 Max while single-core compute badly trails it.
