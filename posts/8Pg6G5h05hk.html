Anthropic Just Released the New Rules of Claude Code

Nate Herk | AI Automation · 2026-11-17 · 186,774 views  ·  Watch on YouTube →
Five session habits from Anthropic's Claude Code lead

Nate turns Lydia Hi's Claude Code talk into concrete settings you can copy today: a slimmer CLAUDE.md, auto mode config, and hard deny rules.

What it is: Nate's breakdown of a talk by Lydia Hi (Claude Code team) on how Anthropic now works with Claude Code. Her team went from ~200 code changes a day in May to 30,000+ a day in September, and engineers now manage dozens of sessions instead of babysitting one. He frames it as five things you used to do by hand in every session. Note: the transcript cuts off during point 3, so points 4 and 5 aren't covered here.

How it works:

  • 1. Steering (old way: watch and correct)
  • On Opus 4.5 you'd watch the session and fix it. People padded CLAUDE.md with IMPORTANT and NEVER in all caps.
  • Lydia's daily driver is now Opus 5.5. On models that strong, those shouted rules backfire: more tool calls, worse results, and the model can go off track.
  • The test for every CLAUDE.md line: could Claude figure this out by reading the code? If yes, delete it.
  • What stays: things Claude can't see in the code. Nate's CLAUDE.md or AGENTS.md is a routing map to his business wiki, brand assets, and finances, all in one folder.
  • Cleanup shortcut: run `/doctor prompt audit` (the transcript spells it "docctor"). It checks your CLAUDE.md and skills against your current model and flags what's no longer needed or is confusing it.
  • 2. Approving (old way: click allow on everything, or skip permissions dangerously)
  • Auto mode is now the default in the terminal and the Claude Code desktop app.
  • A separate classifier checks each command. Tests and installs run freely and it only stops on uncertain ones.
  • Default trust: only your current folder and current repo. Asking it to ship to staging will block the push to your deploy repo, and you approve that manually.
  • Configure in plain English in your settings: trusted repos, buckets, and domains, plus what to always allow or never do. That text is what the classifier sees.
  • Lazy setup: `/auto mode setup` drafts the entries from your project and recent sessions.
  • Anthropic's August study: only ~14% of people caught a clearly dangerous command. Auto mode blocked 89%. About 1 in 10 still got through.
  • 3. Saying no (old way: hope the prompt holds)
  • Set a deny rule in your settings file. It's a hard block that Claude Code checks *before* auto mode gets a say.
  • Lydia's test: if Claude gets this wrong once, can I take it back?
  • Reversible (bad code you can undo): let the model handle it.
  • Irreversible (wiping unsaved work, reading API keys): deny it.
  • Example: deny reads of your `.env` file. A hard-coded permission is very different from a line in the prompt, and that matters for client work.
  • Knowledge-work version: rewriting a draft is fine. Sending an email or deleting files is the same irreversible category.
