My NEW FAVORITE Skill - Claude Code Drives My Whole Computer (Better Computer Use)

Cole Medin · 2026-09-15 · 32,348 views  ·  Watch on YouTube →
A single skill replaces bloated computer-use harnesses entirely.

Cole shows that a well-written skill file plus a CLI is now enough for reliable computer use, which is exactly the lightweight, own-your-tooling philosophy mx-workflow's skills are built on.

What it is: A skill Cole calls "drive screen" that lets Claude Code or Codex control your entire desktop (Mac, Linux, Windows) using nothing but shell commands, with no harness, no MCP server, and no installed computer-use tool.

What he's doing differently:

  • Skill instead of harness — rejects Claude's built-in computer use, Codex computer use, and the open-source harnesses because they are bloated and hard to customize when small issues surface mid-workflow.
  • CLI-only screen control — screenshots, clicks, keystrokes, and window management all happen through OS command-line tools the agent already has access to. The model reads the screenshot and decides the next command.
  • Cross-platform by design — tested on Mac, Linux, Windows, multi-monitor setups, and varied display scaling. One skill file, no per-OS installs.
  • Model capability is the unlock — he credits Fable 5.1 and GPT-6 Astra for making this reliable. Two weeks ago he assumed a dedicated tool was required. It isn't.
  • Born from necessity — he needed to test desktop apps and UIs from open-source projects (Kestra was the example) that browser automation can't reach.

Daily workflows he runs with it:

  • Morning setup — one prompt: "get my morning set up." Agent reads tasks via a task-manager CLI or MCP, opens browser tabs, Obsidian notes, desktop apps, and Docker containers. Saves him 10 to 15 minutes daily.
  • Repo-to-running-app evaluation — hand it a GitHub URL, it researches the web, reads the repo, starts the desktop app, drives the UI to exercise features, then leaves it open for manual follow-up.
  • Video editing — give it an MP4 and say "remove the ums, add B-roll and transitions." No editing tool required.
  • Any UI he can't reach with browser automation — the fallback for everything that isn't a web page.

Security caveats he flags:

  • A skill has none of the sandboxing a full harness provides. The agent can click anything, including destructive dialogs.
  • He explicitly promises a security discussion later in the video. Treat this as "run in a trusted session, review the skill's guardrails before adopting."

Tools & links:

  • Kestra — open-source orchestration platform he used as the desktop-app test case
  • Claude Code and Codex — the two coding agents he runs the skill in

How mx-workflow can improve:

  • Add a `drive-screen` style skill — mx-workflow already leans on skills over agents; a CLI-driven screen-control skill would extend `/mx:e2e` past the browser to desktop apps and Electron builds.
  • Adopt the morning-setup pattern — a `/mx:prime` variant that opens the right terminals, Docker stacks, and dashboards for the mini workspace would mirror his 10-minute daily win.
  • Repo-eval command — his "give it a GitHub URL, research it, boot it, test it" loop is a natural `/mx:second-look` extension for evaluating third-party tools before adopting them.
  • Prefer skills to harnesses — every time you consider adding an MCP server or external tool, ask whether a skill plus existing CLIs gets there first. That's the meta-lesson of the video.
