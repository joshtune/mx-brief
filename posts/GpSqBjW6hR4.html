Testing Sakana's Fugu orchestration model against Claude Opus.

Fugu wraps the multi-agent-router pattern you've been hand-building into one API call inside Claude Code — worth knowing what it actually buys you before you adopt it.

What it is: Nate stress-tests Sakana's Fugu Ultra — a model that's really a multi-agent orchestrator behind a single API — running it inside Claude Code across 38 tasks vs. Claude Opus 4.8.

How it works:

  • Fugu is not a new LLM. It's a small "manager/conductor" model trained only to decompose a task and route subtasks to frontier models.
  • One API endpoint; the conductor delegates to specialists: Claude for writing, GPT-5.5 for coding/bug fixes, Gemini for research/design — plus others by task complexity.
  • Markets itself as matching Fable/Mythos "without export-control risk" (Sakana is a Japanese company; *sakana* = fish, hence the many-fish-into-one-fish branding).
  • Benchmark claims: Fugu > Fable > GPT-5.5 > Opus 4.8 — but only because it's orchestrating them, not out-modeling them.
  • Nate's take: "honestly nothing new" — it's the same main-agent/sub-agent chaining Claude Code already does (spinning up Haiku/Sonnet/Opus workers), just packaged.
  • Demo: a one-shot `/goal` prompt (dictated via Glydo) produced a live-data YouTube dashboard in ~1 hour — refreshing stats, audience pulse, distribution/performance medians, outlier detection, and AI recommendations.

Tools & links:

  • Sakana AI — maker of the Fugu orchestration model

  • AI Automation Society Plus — paid courses + support
