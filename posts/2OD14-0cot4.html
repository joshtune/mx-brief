Running GLM 5.2 inside Claude Code as a cheap Opus alternative.

GLM 5.2 handles ~80% of coding tasks at roughly 5x lower cost than Opus inside the same Claude Code harness — a practical lesson in model-per-task routing.

What it is: Nate swaps Anthropic's Opus for Zhipu's GLM 5.2 as the model backing Claude Code, then stress-tests it across design, coding, and reasoning tasks to see where the cheaper open model holds up.

How it works:

  • GLM 5.2 plugs directly into the Claude Code harness (same `/goal`-style prompting, slash commands, terminal sessions) — it just feels faster and is markedly cheaper per token.
  • Runs on a 1M-token context session; one intro-editing job consumed ~357K tokens and took ~1h15m for a 23-second video (one prompt, raw footage → final cut).
  • Speed is task-dependent, not uniformly faster: website one-shot design finished in 3m59s on GLM vs 14m59s on Opus — but another task took GLM ~24m vs Opus ~5m. GLM wins on lighter work, loses on heavy reasoning.
  • Head-to-head quality test: had Codex generate a homework assignment (to avoid cross-contamination) and then judge both outputs. Opus 4.8 won narrowly — it caught a subtle dedup edge case (`true` vs `1`, `1` vs `1.0`) that GLM missed. Verdict: GLM solid, Opus more precise.
  • Design quality: GLM produced landing pages nearly indistinguishable from Opus's (the tell was Opus's signature font/"weird Fs"), plus a creative free-form HTML "anatomy of attention" page with animated star background.
  • Billing/quota: tested on Z.AI's $60/mo plan; ~4-5 hours of hammering across 5 concurrent sessions used just over half the 5-hour quota and ~10% of the weekly quota.
  • Core thesis: you only truly need Opus for maybe 10-20% of tasks; route the other 80% to cheaper models like GLM 5.2 or Sonnet-tier.
