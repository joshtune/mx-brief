How To EASILY Run Local AI Models

Matt Wolfe · 2026-08-26 · 9,753 views  ·  Watch on YouTube →
LM Studio makes running Qwen 27B locally trivial.

If you're prototyping AI features into a web app, a local 27B model on your dev box means free, unmetered iteration before you ever wire up a paid API key.

What it is: A two-minute walkthrough of downloading and running Qwen 3.8 27B locally via LM Studio — no GPU server required.

How it works:

  • Qwen 3.8 27B is a 27B-parameter variant that Matt claims runs on consumer-grade hardware
  • Install LM Studio (free), open model search, search "Qwen 3.8", grab the official Qwen build from Hugging Face
  • Pick a quantization: 4-bit, 5-bit, 6-bit, or 8-bit. Lower bits = smaller file, less compute, slightly dumber model. Rule of thumb: run the highest bit depth your machine tolerates
  • LM Studio's model cards tell you up front whether a given quant will actually run on your machine — no trial-and-error downloads of 20GB files
  • After download: My Models → cog icon → Use in New Chat. Uncensored variants are selectable the same way
  • The model handles reasoning, code generation, and general chat like you'd expect from a current-gen model

Tools & links:

  • LM Studio — free desktop app for downloading and chatting with local models; also exposes an OpenAI-compatible local server
  • Hugging Face — where the official Qwen weights live; LM Studio pulls from here
  • futuretools.io — Matt's AI tool directory

The bit that's actually useful for web dev (not in the video): LM Studio ships a local server on `localhost:1234` that speaks the OpenAI chat-completions API. Point your app's client at that base URL and you get a zero-cost drop-in for local dev — prompt iteration, RAG chunking experiments, structured-output testing — without burning API credits or shipping user data anywhere. Swap the base URL back for prod.

Caveats: "Runs on consumer hardware" is doing heavy lifting. A 27B at 4-bit wants roughly 16–20GB of RAM/VRAM; on a 16GB laptop you'll be swapping and slow. Local models also lag frontier models badly on tool-calling reliability and long-context work, so don't benchmark your production prompts against them.

Why it matters for you: Cheap local inference is a dev-environment win — iterate on prompts for free, then ship against a real API.
