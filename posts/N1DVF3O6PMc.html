Your OS Changes Everything for Local AI

Alex Ziskind · 2026-07-29 · 32,656 views  ·  Watch on YouTube →
Windows vs WSL vs Linux for local LLM inference.

Same box, same chip, three OS choices — and one of them triples your prompt processing speed, which matters more than the hardware spec sheet when you're picking a Mac mini alternative.

What it is: A three-way OS shootout on the GEEKOM A9 Max (AMD mini PC, ships with Windows) running local LLMs — Windows native vs WSL vs bare-metal Linux.

The machine:

  • GEEKOM A9 Max — AMD-based mini PC, Windows out of the box. This is the Mac mini competitor in the room: same small-box form factor, but you get to choose the OS, which is the whole point of the video.
  • No pricing given in the transcript. Alex's usual framing puts these AMD mini PCs in the same rough bracket as a mid-spec Mac mini, but he doesn't do the dollar comparison here — this is purely a software-stack test.

The results (decode = token generation, prefill = prompt processing):

  • Windows + Ollama (default): worst case. Ollama on Windows runs 100% CPU, GPU completely idle. If you installed Ollama and thought "this chip is slow," this is why.
  • Windows + llama.cpp with Vulkan: beats default Ollama outright. This is the fix.
  • Windows + Lemonade: ties Vulkan on decode.
  • WSL: gives up roughly 1/6 of throughput vs Windows native. Acceptable tax if you want the Linux toolchain without dual-booting. Needs Kisak Mesa installed to be viable.
  • Bare-metal Linux: all three backends land within a few percent of each other on decode — so decode is basically a wash across every OS.
  • The one that matters — long prompt prefill: Linux with RADV (the Mesa AMD Vulkan driver) is ~3x faster than Windows. That's the benchmark that made him double-check his numbers.

The verdict:

  • Long-context work (RAG, big system prompts, code files pasted in) → bare-metal Linux + RADV, no contest.
  • Chat-only, short prompts → Windows is fine, just don't use stock Ollama.
  • Want Linux tooling without the reboot → WSL + Kisak Mesa, eat the ~17% throughput hit.

Tools & links:

  • llama.cpp — the inference engine doing the actual work; use the Vulkan backend on AMD
  • Ollama — convenient, but CPU-only on Windows for this chip
  • Lemonade — AMD's local LLM server stack, ties Vulkan on decode
  • RADV / Kisak Mesa — Mesa's AMD Vulkan driver; the Kisak PPA is what makes WSL usable
  • Gear links from the description: MSI EdgeXpert, ASUS GX10, 2-port 400Gbps switch, 4-port 400Gbps switch

Why it matters for you: If you're weighing a mini PC against a Mac mini for local AI, this is the hidden variable — the AMD box's headline numbers are an OS choice away from being 3x better or 3x worse, whereas a Mac mini gives you Metal-optimized inference with zero configuration.
