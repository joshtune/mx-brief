My AI Memory Now Follows Me Across Every Tool!

Cole Medin · 2026-06-19 · 7,692 views  ·  Watch on YouTube →
Portable, encrypted AI memory shared across coding agents.

If you're juggling Claude Code, Codex, and other agents, this shows how to stop re-teaching each one your context by putting memory in a tool-agnostic MCP layer — directly relevant to how you'd architect mx-workflow's memory.

What it is: Cole replaces his Claude-Code-locked "second brain" memory with Walrus Memory — a decentralized, encrypted memory layer that any AI tool can read/write via MCP.

The problem he's solving (what's different now):

  • He's no longer Claude-Code-only. He now bounces between Claude Code, Codex, and Pi, picking the best tool per task.
  • His prior memory system was baked into Claude Code + his second brain → it locked him into one tool. Switching tools meant losing all project/personal context.
  • The fix: pull memory *out* of any single agent and into a shared, portable layer.

How it works:

  • One-prompt setup: copy the install prompt from Walrus's homepage, paste into any AI coding assistant, and it wires up the Walrus Memory MCP server for you.
  • Once connected, the MCP exposes tools to: remember key info, analyze/extract memories from a large blob of text, and search stored memories.
  • Demo: he pastes a chunk of second-brain notes, says "use Walrus to remember this" → it extracts 20 facts, encrypts, and stores them.
  • Cross-tool retrieval: in a separate Claude Code session he asks "search my Walrus memories for the Dark Factory tech stack" → correct full answer. Same exact query in Pi → same answer, no setup beyond connecting the MCP.
  • Decentralized + encrypted + user-owned: memories aren't on a vendor's infra. Supports access control + delegate keys so different systems (or people) get scoped access.
  • An SDK lets you embed the same memory layer into your own apps, not just coding agents.

Tools & links:

  • Walrus Memory — tool-agnostic, encrypted, decentralized memory layer exposed over MCP; one-prompt install, SDK for custom apps (link in video description — not provided in transcript)
  • Claude Code, Codex, Pi — the three agents he rotates between, all sharing the one Walrus MCP

Caveat (signal check): This is effectively a sponsored/promo segment — heavy on Walrus's pitch (encrypted, you-own-it, one prompt), light on hard verification. "Decentralized + encrypted" claims are unaudited here. Treat as a pointer to evaluate, not an endorsement.

Why it matters for you: mx-workflow currently has its own file-based memory convention (MEMORY.md + per-fact files). If you're ever multi-agent, the architectural lesson is the same: memory belongs in a shared layer with a stable interface (MCP/SDK), not embedded in one harness. Worth evaluating an MCP memory server as a portable backend so your facts survive a tool switch — but weigh it against the simplicity and auditability of your current plaintext files.
