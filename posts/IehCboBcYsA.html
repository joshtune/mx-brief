How to automate your photo library

Matt Wolfe · 2026-11-12 · 9,618 views  ·  Watch on YouTube →
Sorting 5,600 photos with OpenAI's new decision API

It's a quick look at a cheap, fast classification endpoint you could drop into any web app, but it's a demo, not a tutorial.

What it is: Matt runs his iPhone photo library through OpenAI's new 'decisions' API. It labels each photo (screenshot, blurry, keeper, too far away) and an app files them into albums.

How it works:

  • You send images and a list of labels, and the model picks exactly one label per item.
  • One request takes up to 128 photos.
  • Matt says it runs up to 10x faster than the regular API, using 'GPT6 Luna'.
  • Pricing as stated: $0.10 per million input tokens, and output is free.
  • He also scored every photo from 58 trips on sharpness and framing. That produced one 'best of all trips' album.
  • The video gives no implementation details, code, or accuracy numbers. Treat the speed and price claims as unverified until you've checked the docs.

Tools & links:

  • Decision model docs — API guide for the decisions endpoint
  • Decisions playground — try it in the browser without writing code

Why it matters for you: If your web app needs bulk classification, such as moderating uploads, tagging content, triaging tickets or ranking user media, a pick-one-label endpoint with free output could replace a pile of prompt-and-parse code. Skim the docs and skip the rest of the video.
