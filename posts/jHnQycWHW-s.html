Self-host Gitea so you and your AI agents own the code

Chuck has run his own GitHub replacement for six months and treats it as the home base where his AI coding agents open pull requests on a server he controls, which is the home-lab-meets-AI workflow you want to copy.

What it is: A walkthrough of installing Gitea, a free, open-source, GitHub-style Git server, with Docker on an Ubuntu box (a VPS or a home-lab VM), then connecting AI agents to it.

How it works:

  • Why bother: GitHub outages have been frequent, and Microsoft holds your code. Self-hosting means you stay up when GitHub is down.
  • The AI angle: Chuck's pitch is an agent opening a pull request on a server you own. It gets even better with local AI agents, because the whole loop stays on your own hardware.
  • Chuck's usage: He has run Gitea for six months and says he won't go back.
  • Git as agent bookkeeping: This is a sequel to his recent Git video. Git and a remote server keep your agents' output organized, so rapid AI-built features don't turn into a mess.
  • Hosting options: The setup works on a cloud VPS or on-prem in a home lab. Gitea should run anywhere Docker runs.
  • Demo stack: A fresh Ubuntu 26.04 VPS (Hostinger KVM 2) with Docker installed. He logs in over SSH as root and says hardening comes in a later step, because the box is exposed to the internet until then.
  • Coding hub idea: The same always-on VPS can also run Claude Code or Codex, which makes it a persistent place for agents to work.
  • Beyond the transcript: The transcript cuts off before the install. The video tags point to Docker Compose, a Gitea MCP server, and push mirroring. Chuck also says the full docs are in the description.
