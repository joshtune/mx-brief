Sponsored pitch: OutSystems MCP gives agents app-level context

Mostly skip it: it's an OutSystems ad with no repo, no technique and no skill patterns you can lift for mx-workflow, though the 'agent needs runtime context' idea is worth a minute.

What it is: A sponsored walkthrough of the OutSystems MCP, which connects Claude Code, Codex or GitHub Copilot to the OutSystems Developer Cloud so an agent can see the running app, not just the repo.

How it works:

  • The agent first looks up real entities, screens, logic and roles in the app and maps what depends on what, before it changes anything.
  • It then hands the build to Mentor, OutSystems' built-in coding agent, which publishes it.
  • If something breaks after deploy, the same session pulls logs and traces to diagnose it.
  • The agent runs as you, with your OutSystems permissions. If you can't do something, neither can it.
  • The Personal edition is free and ships with the MCP enabled, so you can try it with whatever coding agent you already use.

Tools & links:

  • OutSystems MCP / Developer Cloud: exposes the app's data model, dependencies, deployments and logs to your agent. The URL is only in the video description, not the transcript.
  • Mentor: OutSystems' built-in coding agent, which does the build and publish step.
  • Claude Code, Codex, GitHub Copilot: the compatible agent clients.
  • No GitHub repos are mentioned. This is not an Archon or open-source video.

What's different from Cole's usual content:

  • It's a paid partnership. There is no harness engineering, skill design or orchestration, which is what you normally watch him for.
  • It is tied to a proprietary low-code platform. There is no code or demo detail in the transcript.

Why it matters for you: Little to take directly. The general lesson for mx-workflow is that agents do better when a skill or MCP gives them live runtime context (deployments, logs, dependency maps) before they edit. You could add a pre-change 'map dependencies' step and a post-deploy 'pull logs and diagnose' step to your build and RCA skills (`/mx:rca`, `/mx:build`). Don't adopt OutSystems for it.
