My AI Agents Write Code Faster Than I Can Verify It

Cole Medin · 2026-11-16 · 1,722 views  ·  Watch on YouTube →
Sponsored take: AI code outpaces human verification

Short and thin, but it gives you a clean mental model (intent × guardrails × verification × evidence) to audit whether mx-workflow's agents can merge anything unchecked.

What it is: A sponsored (Sonar) ~2-minute riff on Sonar's State of Code report. It's a framing video, not a tutorial. There's no demo, no repo, and no new tooling.

How it works:

  • The stat: 76% of devs and eng managers say they generate AI code faster than they can verify it. Cole says he's in that group.
  • His setup: he runs "software factories" where agents pick up issues, build them, and open PRs around the clock. Most of his time now goes to deciding whether to trust what ships.
  • The worrying trend: as AI code gets better, people check it less. Fewer devs say they always check AI code before committing. Concern that code is too well-written to spot bugs rose from 31% to 42%. The bugs that survive are subtle and look reasonable.
  • Adoption: 5% of teams run AI software factories today and 34% expect to within a year.
  • The formula: code confidence = intent × guardrails × verification × evidence. It's multiplicative, so any factor at zero means zero confidence. Great context with no independent verification still ships unchecked code.
  • His one concrete rule: agents can write whatever they want, but nothing merges until a check the agent doesn't control says it passes.
  • What's different vs. earlier Cole content: the emphasis has moved from "how to prompt and orchestrate agents" to "how to trust their output". Orchestration isn't the bottleneck anymore.

Tools & links:

  • Sonar 2027 State of Code report — the source of the stats. Cole says the link is in the video description, and none is given in the transcript.
  • No repos, CLIs, or Archon mentions in this video. It's a sponsor spot, so don't expect implementation detail.

Why it matters for you: Audit mx-workflow against the four factors and steal the independence rule:

  • Independent gate: make sure the check that blocks a merge isn't the same agent (or context) that wrote the code. `/mx:validate`, `/mx:ratchet`, `/mx:reject` and `/mx:second-look` are already in this territory. Check they run outside the author agent's control, e.g. in CI.
  • Evidence: have `/mx:pr` attach proof (test output, ratchet deltas, reviewer verdicts) so a human can judge trust quickly instead of re-reading the diff.
  • Intent: make sure the PRD or plan is machine-checkable, so verification has something to verify against.

Verdict: Worth 2 minutes for the formula. Skip it if you want implementation detail.
