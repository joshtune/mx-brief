Omarchy auto-diagnoses app crashes with AI agents

DHH shows an OS-level crash-to-PR loop where AI skills diagnose, file, and fix bugs — a blueprint for wiring agents into your own lab's failure handling.

What it is: A short clip (from the full NetworkChuck video) of DHH describing Omarchy's new crash-handling pipeline: any app crash triggers an AI diagnosis that can escalate all the way to a GitHub PR.

How it works:

  • App crashes in Omarchy (e.g. Nautilus) → popup: "Nautilus crashed, click to diagnose with AI"
  • Click loads a diagnose-crash skill into your preferred agent harness — Pi, Claude Code, OpenCode, whatever you've configured
  • Agent pulls crash info and runs the diagnosis
  • After diagnosis it chains a second report-issue skill: is this actually an Omarchy bug? Walk the checklist
  • If yes and you've set up the GitHub CLI (Omarchy nudges you to on first boot), it files the bug straight to the Omarchy repo
  • On the maintainer side, DHH has an agent review incoming reports and turn them into PRs if it can reproduce the issue
  • Net effect: user-side agent + maintainer-side agent = OS iteration at a totally different pace

Tools & links:

  • Omarchy — DHH's Arch + Hyprland distro with the crash-diagnose skills baked in
  • GitHub CLI — required for the auto-report step
  • OpenCode — one of the supported agent harnesses
  • Claude Code — another supported harness
  • Full NetworkChuck video — the complete walkthrough
  • NetworkChuck's DHH interview — longer conversation on Omarchy and AI workflows

Why it matters for you: This is the home-lab AI pattern worth stealing: harness-agnostic skills that trigger on failure events, chain diagnose → report → fix, and close the loop without a human babysitting the terminal.
