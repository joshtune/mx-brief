I Gave an AI Engineer Access to My Whole Business

Nate Herk | AI Automation · 2026-09-04 · 14,794 views  ·  Watch on YouTube →
Devin indexes a business repo, ships a waitlist page PR.

A 60-second look at the 'repo as company brain' pattern: point an autonomous engineer at one GitHub repo so you stop re-explaining your business every task.

What it is: Nate hands Devin (Cognition's autonomous AI engineer) full access to the single GitHub repo that runs his business, then has it document the repo and ship a feature via pull request.

How it works:

  • Devin spins up its own cloud VM per task with a terminal, code editor, and browser. No local setup.
  • Step 1: it indexes the entire repo and generates a wiki, including architecture diagrams, per-module summaries, and links back to source files (this is Devin's DeepWiki feature).
  • Step 2: Nate asks for one thing, a waitlist page for his AI certification program.
  • Devin pulls the program details from the repo, discovers the brand fonts and colors already in the codebase, builds the page, and opens a PR for review.
  • Devin can be triggered from Slack or Linear by tagging it, and you can run unlimited Devin sessions in parallel.
  • The core play: the repo is the context layer. Every new task inherits the business knowledge instead of Nate re-explaining it in a prompt.

Tools & links:

  • Devin — Cognition's autonomous AI software engineer, runs in its own cloud sandbox
  • Cognition — the company behind Devin
  • DeepWiki — Devin's auto-generated repo documentation with architecture diagrams (free for public repos)
  • GitHub — where Devin reads the repo and opens PRs
  • Slack — tag Devin to kick off a task
  • Linear — assign Devin an issue to kick off a task

Caveats:

  • Transcript is a short promo-style walkthrough, not a step-by-step tutorial. No repo link, no Devin config, no PR shown in detail.
  • No pricing, guardrails, or review process discussed. Full repo access to an autonomous agent is a real security decision the video skips.

Why it matters for you: If you keep operational context in a repo, this is the cheapest way to make an AI engineer productive on day one, and the same pattern works with Claude Code or Codex if you don't want Devin's cloud VM model.
