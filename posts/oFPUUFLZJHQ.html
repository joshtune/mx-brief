Your Coding Agent Wastes SO MANY Tokens Just Finding Code - Here's the Fix

Cole Medin · 2026-09-28 · 2,883 views  ·  Watch on YouTube →
Sonar Vortex replaces agent code search with direct lookups

It's a sponsored but concrete look at cutting the 'find the code' token tax, which is the cheapest win available for your mx-workflow agents and skills.

What it is: A sponsored demo of Sonar Vortex, a code-graph tool that lets a coding agent look up code relationships directly instead of grepping and reading files.

How it works:

  • The problem: For any non-trivial change, the agent greps, then reads every candidate file to confirm it applies. Search is cheap; reading burns context before a single line is edited.
  • Search is a guess: Code named differently than the agent expects gets missed, so a change can be correct everywhere it found and still incomplete.
  • The reframe: The agent is really asking one question: *what code applies to this change?* Grep can't answer that. A graph can.
  • Direct lookups: Vortex answers things like which classes implement an interface, what calls a function, and what it calls, down to file and line.
  • Local graph: Built on your machine, with no compiler or language server. It refreshes in about a millisecond after an edit, which matters because code is usually mid-change and uncompilable during an agent turn.
  • Demo result: Same prompt in Claude Code. Search-and-read took about 80,000 tokens. With Vortex, the same lookup plus a follow-up context load came in at roughly the same total.
  • Sonar's own study: 6 refactoring tasks, 10 runs each, showing 6–34% token savings.
  • Language support: Java, C#, JavaScript, TypeScript, Python, Rust.
  • Requirements: SonarQube Cloud plus the Sonar Agent Essentials add-on.

Tools & links:

  • Sonar Vortex — the semantic navigation tool. Cole says the link is in the video description; no URL is given in the transcript.
  • SonarQube Cloud + Agent Essentials add-on — the paid platform it runs on
  • Claude Code — the agent used in the demo

Caveats:

  • Sponsored: Sonar paid for this, and Cole says so.
  • Weak numbers: The 6–34% range comes from Sonar's own study, and the demo doesn't clearly show savings ("about the same").
  • Not open source: No repo is mentioned, unlike Cole's usual Archon-style tooling.

Why it matters for you: For mx-workflow, the transferable idea is not Sonar. It's giving agents structured lookups (callers, implementers, symbol references) instead of letting them grep-and-read. That could mean:

  • Adding an MCP-backed code-graph step to `/mx:plan` and `/mx:prime`
  • Trimming the exploration phase in the review agents
  • Checking whether an open-source graph or LSP-style MCP could do this without a paid platform
