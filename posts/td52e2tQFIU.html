The Biggest AI Coding Agent Upgrade Is Already on Your Machine?!

Cole Medin · 2026-09-25 · 14,935 views  ·  Watch on YouTube →
Mine your own Claude Code conversation logs to improve the agent.

Cole turns the JSONL transcripts Claude Code already writes to disk into a structured, queryable dataset that surfaces concrete token-efficiency and reliability fixes — a low-effort feedback loop worth stealing for mx-workflow.

What it is: A method for extracting insights from the conversation logs every coding agent (Claude Code included) already writes to disk, turning them into structured data you can analyze to make the agent more efficient and reliable over time.

How it works:

  • Claude Code (and other agents) log every prompt, tool/MCP call, and agent thought to `.jsonl` files on your machine, split by project.
  • These files are dense and hard to parse manually — the fix is extracting them into structured tables instead of eyeballing raw JSONL.
  • Cole builds three core tables: sessions, tool calls (every tool/MCP invocation across conversations), and agent turns.
  • He uses Databricks (free tier) as the storage/analysis layer for these tables.
  • Because Claude Code purges transcripts after 30 days by default, you need a permanent store before you can do longitudinal analysis — this is the first problem his setup solves.
  • Quick-and-dirty alternative (no pipeline needed): just prompt Claude Code directly — "Do a deep dive into our past conversations to identify opportunities to make our coding agent like Claude Code more efficient or reliable. Suggest the top 10 improvements in a concise bullet point list." He explicitly bounds the output count because pre-Opus-5.5 models would dump huge, low-value change lists.
  • Claude Code already knows where its own transcripts live — you can literally ask it "Where are all Claude Code conversations stored on my machine?" or search for `*.jsonl` to find/copy them yourself.
  • The end goal: use the agent to analyze its own history and find (a) token-inefficient patterns, (b) recurring failure modes to encode into rules/skills, and more.

Why it matters for you: For mx-workflow, this is a direct blueprint — snapshot your own `~/.claude/projects/**/*.jsonl` history before the 30-day cleanup, structure it (even just a simple SQLite/DuckDB table of sessions/tool-calls/turns), and run a bounded "top 10 improvements" prompt periodically to feed back into your CLAUDE.md rules and skills, closing the loop between what your agents actually do and what your project instructions say they should do.
