DeepSeek Just Built the Next Generation of Coding Agents

Cole Medin · 2026-08-20 · 8,878 views  ·  Watch on YouTube →
DeepSeek's open-source, all-plugins coding agent harness.

It's the clearest argument yet that the winning harness is the one you can rewrite — which is exactly the bet mx-workflow is making with skills and agents.

What it is: DeepSeek open-sourced its own coding agent harness — 165k+ GitHub stars in under a week — where *every* component, including the harness internals, is a togglable plugin.

What Cole is doing differently here:

  • Treating the harness itself as the product, not the model. His framing: you're locked into Claude Code's and Codex's models *and* their internals, with zero access to the agent loop.
  • Evaluating it as a daily driver that calls Claude Code and Pi as subagents — the harness is the orchestrator, the polished agents are the workers.
  • Betting explicitly on self-extensible agents: an agent that edits its own loop needs a framework with a standard for adding and disabling functionality. Plugins are that standard.
  • Being honest that it's rough — he is *not* telling you to switch off Claude Code today. It's a directional signal, not a migration.

How the harness works:

  • Plugins are the atomic unit. The UI, the tools, and the inner harness mechanics are all composable plugin units stitched together.
  • Each component toggles on/off individually — you can strip the agent down to nothing and rebuild it around your workflow.
  • Plugin marketplace for third-party installs.
  • Creator mode — a built-in mode that walks the agent through generating a plugin from a plain description. The harness ships pre-wired to extend itself.
  • Model-agnostic: no lock-in to a specific provider's models.
  • Install via npm or run from source; the README has a one-command path.

The trade-off he lands on:

  • Minimalist harness (DeepSeek) → maximum customization, least polish.
  • Middle ground (Pi) → self-extensible via extensions, more refined. Original motto: *"There are many coding agents out there, but this one is mine."*
  • Out-of-the-box (Claude Code / Codex) → all the power immediately, zero access to internals.
  • His verdict: start from a foundation you can build on and customize to *your* process — that compounds further than any out-of-the-box agent.

Why it matters for you: mx-workflow is already a plugin — the upgrade path Cole is pointing at is (1) make every mx skill/agent independently togglable so you can run a stripped profile per repo, (2) add a *creator mode* command that generates new mx skills from a description instead of you hand-writing them, and (3) stop assuming mx sits *inside* Claude Code — the interesting version has mx as the harness that dispatches Claude Code and other agents as swappable subagent workers.
