Not big enough

Alex Ziskind · 2026-09-24 · 45,768 views  ·  Watch on YouTube →
Four M3 Ultra Mac Studios clustered, still not enough

Alex clusters four fully-loaded M3 Ultra Mac Studios (2TB combined unified memory) just to run a 34B model at 24.8 tok/s — a real data point on what it costs to go bigger than a Mac mini for local AI.

What it is: Alex SSHes into a 4-node Mac Studio cluster (M3 Ultra, 512GB each) sharing memory via tensor parallelism, then runs Qwen 34B Instruct to see how it performs.

How it works:

  • 4x Mac Studio M3 Ultra, 512GB unified memory each = 2TB combined pool
  • Networked/racked together, controlled by SSH into a "head node"
  • Tensor parallelism splits the model across all four machines
  • Qwen 34B Instruct runs at 24.8 tokens/sec across the whole cluster
  • Takeaway line from Alex: even this setup "might be not big enough" — i.e., throughput is underwhelming relative to the hardware thrown at it

Cost vs. Mac mini:

  • A maxed-out M3 Ultra Mac Studio (512GB) runs ~$9,500 each — four of them is ~$38,000+ in Macs alone, before the rack
  • A Mac mini caps out around 64GB unified memory (~$2,200 maxed M4 Pro) — it simply cannot load a 34B model at usable quant levels, let alone cluster
  • Net: this rig is roughly 17x the price of a maxed Mac mini, and the payoff is a model that's still "not big enough" — a caution against assuming more Apple silicon linearly buys you bigger local models

Tools & links:

  • Server rack (tall) — used to house the clustered Studios
  • Server rack (short) — alt rack option

Why it matters for you: If you're pricing out local AI hardware against a Mac mini, this is the ceiling-testing data point — 2TB of Apple unified memory across four $9.5k machines still bottlenecks on a mid-size model, so a mini is fine for small models but this class of cluster is what "go big" actually costs.
