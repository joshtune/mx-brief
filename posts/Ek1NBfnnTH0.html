Keeping your AI operating system organized and hallucination-free.

If your agent context is sprawling, Nate names the four ways it silently rots and gives you a free self-auditing skill to catch the damage.

What it is: Five organizational tricks for keeping an "AI OS" (a structured project of routing rules, wikis, and folders that agents read from) accurate as it scales — anchored by a free OS-audit skill.

How it works:

  • OS audit skill — Run it against your project; it reads everything (routing rules, folders, wikis), then reports ~10 weak spots and proposed fixes as a yes/no gate. It does *not* act — pure exploratory phase.
  • Audit deliverable — Auto-creates an `audits/` folder at project root (if missing) and drops a markdown file listing findings + fixes.
  • Four context failure modes (the framing for why organization matters):
  • Poisoning — a false fact sits among correct facts; the agent surfaces it downstream (email, skill, automation). Easiest to fix: add verification — web search, cross-check against a live DB, or human-in-the-loop when confidence is low.
  • Bloat — too much data loaded; needle-in-haystack + context rot make it hard to pull what's relevant. Harder to fix; his "expertise vs. situational" context split is the lever (teased, not yet shown in transcript).
  • Confusion — (transcript cuts off here).
  • Clash — contradictory facts in context.
  • Two context types: expertise vs. situational — used to fight bloat by separating always-true knowledge from moment-specific data.
